# 天气输入可信度与公开气候基准

本批用于关闭 CL-P01 的限定输入准入缺陷，并建立真实天气和原生天空推导证据。不是设计日负荷、气象质量认证或实楼校准交付。当前开发复评维持 75/100，不能以测试条数代替专业能力得分。最终回归、版本和发布状态见 [证据索引](WEATHER_QUALITY_EVIDENCE.json)。

## 实现与调用链

1. 原件上传与版本登记保持不变。`Domain.gate → validate_epw → inspect_epw` 返回与原件 SHA256、策略版本、校验器字节摘要绑定的回执。
2. 站点坐标、时区、高程、单年时钟及关键物理字段接受有限数值和明确范围检查。错误指出源行、字段、单位。单独的人工作业确认不能绕过校验。
3. 关键温湿度、气压、直射/散射辐射和风参数缺测拒绝运行；可选字段缺测、雨况未知及具备推导条件的长波缺测逐类计数，保留首末行定位。应用插补次数为零，未改写输入。
4. `core.run_simulation` 在引擎版本查询和仿真之前，对归档后的实际天气再次检查，防止绕过 API 直接进入物理核心。`weather-quality.json` 加入原有制品哈希清单；读取时检查天气/回执/运行绑定。
5. API 结果、HTML、PDF、JSON 和原始证据 ZIP 使用同一回执。失效或失败时当前天气回执、能耗与碳结果不作为有效值输出；历史原件和运行文件保留。
6. 界面按所选方案核验准入，未确认、失败、加载中或过期响应均不能启用运行按钮。服务端仍在提交时独立重核验。天气条件面板使用中文名称、分层详情和适合阅读的字号。

## 支持政策与边界

支持 EnergyPlus 9.0 的单年度、每小时一行 EPW，8760/8784 小时；`DATA PERIODS` 当前只接受 1/1–12/31 的月/日语法。全文件 0 分钟旧版约定和 60 分钟约定分别接受，混用拒绝。TMY 来源年份允许跨年组合，并明确不等于一个连续实测年。时区范围按固定 9.0 字典采用 −12 至 +12；超出本应用政策不代表地理上不存在该时区。

政策区分原生推导、前值/默认值和不参与常规天气计算的字段。天空长波缺失允许记录为原生推导条件，但必须有有效干球、露点和不透明云量；IDF 自定义天空属性仍须复核。雨况缺测会令引擎雨标志为否，不证明无雨；反照率、降水等可选缺测仍可能限制湿润、植被和相关模型用途。允许有条件仿真不是证明数据完整或规范合规。

本批未验收全部设计条件、典型周期和地温头的工程适用性；未完成全面气象一致性、实际年模型绑定、不同格式天气转换或设计日站点一致性认证。公开气候对照保持模型、设计日、时段、地温和定容输入不变，仅改变天气；不得把它们当作各地可直接交付的设计。

技术依据：[固定 9.0 数据字典](https://bigladdersoftware.com/epx/docs/9-0/auxiliary-programs/energyplus-weather-file-epw-data-dictionary.html)及[9.0.1 引擎原码](https://github.com/NatLabRockies/EnergyPlus/blob/v9.0.1/src/EnergyPlus/WeatherManager.cc)。原码副本摘要为 `e6974a64d8cbe9429e15728af7be78e937ceee251ed0ca8fa0297c4503ebd0a9`；副本仅供查阅，未作为程序执行。

## 真实运行与独立核验

五个安装包公开 TMY3 站点均保留文件摘要及配套 DDY 摘要。最终 Windows/Linux 的同一固定模型得到以下全年场地能耗；跨平台一致性不是另一个独立能耗模型的验证。

|站点|全年场地能耗 kWh|天气条件类别|原生 Warning 数|
|---|---:|---:|---:|
|San Francisco|50,479.16|5|4|
|Golden-NREL|57,193.23|4|2|
|Tampa|56,639.41|5|4|
|Chicago-OHare|62,539.21|5|4|
|Dulles|58,431.81|5|4|

所有 Warning 保留，仍要求工程师核对；没有由这些数值宣布规范合格或最优改造。五区参考面积为 927.2 m²；碳基准选择 `none`，没有把未知地区碳因子默认为真实排放。

另生成两个有明确合成标记的恒定天气：干球 20°C、露点 10°C、无太阳辐射、不透明云量分别 0/10，全部长波列为缺测。独立计算 `ε=(0.787+0.764 ln((10+273.15)/273.15))×(1+0.0224N−0.0035N²+0.00028N³)` 和 `Tsky=(20+273.15)ε^(1/4)−273.15`，预设绝对容差 10⁻⁶°C。两平台分别从原生 SQL 提取全年 8760 条小时天空温度；清空/全云期望值分别为 5.3394144205228145°C、15.492411461655763°C，最大绝对偏差均为 0。验证脚本不调用产品代码生成期望天空温度。

每个平台最终基准含 5 次公开气候、2 次合成天空及 1 次认证 API 实际仿真；另为新物理代码重新运行 baseline/R1/R2 三方案。历史运行不改写来消除 stale。`scripts/verify_weather_reference.py` 为可重放入口，需匹配 9.0.1 引擎和对应公开天气包；大体积 SQL/原件保存在隔离验收目录，仓库提交紧凑回执及哈希。

## 缺陷与复现记录

### CL-P01 · 高 · 关键天气缺测/非法输入通过准入

- 对应功能：天气预检、证据准入、物理计算入口。
- 描述：旧校验只对四列检查有限性，未识别关键缺测值、气压范围、太阳辐射及站点坐标。
- 复现：复制公开 Golden 天气，分别将第9行干球置99.9、湿度置999、气压置−1、直射置NaN，或将LOCATION纬度置900；逐份上传、登记、人工确认并请求gate。
- 预期：定位异常，拒绝仿真，保留源文件。
- 原实际：五个异常与正常对照均返回can_simulate=true；未提交仿真，不能据此声称曾产生错误能耗。
- 修复实际：五个异常在认证API均阻断；直接核心入口对缺测直射拒绝，版本查询/仿真调用均未执行。正常公开天气通过且附可见条件。
- 证据：修改前 `preflight-probe.json` / `api-gate-probe.json`；50项天气契约测试、双平台新基准、浏览器条件与拒绝记录。
- 修复建议/处理：字段政策、单位/范围/日历、可追溯回执和核心复检已实现；上述未支持气象/模型范围继续单列。

### CL-P02 · 中 · 运行中删除临时调试文件导致巡检中止

- 对应功能：原生运行资源监督、Linux稳定性。
- 复现：首轮Linux公开San Francisco仿真遇到 `eplusout.dbg` 在目录枚举后、stat前被引擎删除；独立夹具精确模拟这一顺序。
- 预期：合法运行可继续，结束后的制品检查保持严格。
- 原实际：FileNotFound触发ExecutionError，结果失败而非伪造成功，首轮运行和日志保留。
- 修复实际：仅运行中的巡检忽略已消失项的ENOENT；权限错误、链接、特殊文件、节点和容量上限继续拒绝，结束后检查和归档不采用该例外。新Linux全部8项天气真实运行通过。
- 证据：`linux-weather-v1.log`、原失败运行摘要；5项确定性反例及既有资源监督测试；新版本双平台基准。
- 修复建议/处理：已限定修复。不把周期性巡检称为操作系统峰值磁盘配额；不据此关闭既有RS-09 CPU触发顺序调查。

### CL-P03 · 中 · 无效准入仍显示可点击的仿真按钮

- 对应功能：仿真表单。
- 复现：确认含缺测干球的天气后进入仿真页。
- 预期：按钮禁用并说明所选方案的阻断原因，切换方案后重新核验。
- 原实际：按钮仍可点击；服务端仍拒绝，不是成功绕过准入。验收断言 `Invalid weather is runnable` 表述过强，实际只证明按钮未禁用。
- 修复实际：baseline/R1均在错误天气下禁用；正常参考方案切换后可运行。待返回、网络失败、过期异步回复有专项保护。
- 证据：首次浏览器断言及截图、`simulation-gate.test.js`、最终候选版浏览器/API/报告。
- 修复建议/处理：已按方案绑定按钮状态，服务端校验保留。

### CL-P04 · 中 · 保存复核后快速打开的导入窗口被刷新关闭

- 对应功能：资料复核和继续导入。
- 复现：保存复核，窗口刚关闭即打开导入窗口；未完成的项目刷新随后替换DOM。
- 预期：下一窗口保留并可输入。
- 原实际：导入窗口消失，文件定位超时；之后对不存在复核表单的操作亦超时，均保留在浏览器失败记录。
- 修复实际：先完成项目刷新，再结束复核窗口。快速连续打开并填写来源字段成功，未提交额外原件。
- 证据：`browser_reject.cjs`及失败记录、`browser_v4_fast_review.cjs`与稳定表单快照；最终同一复核实现随候选前端验收。
- 修复建议/处理：已修复正常保存链的顺序；不等于全站所有取消、重入和模态交互均已验收。

## 最终局部验证结果

最终Windows：981通过、25跳过、6子测试，1195.94秒；Linux：990通过、16跳过、6子测试，602.72秒；前端77项、语法、构建通过。双平台全量存在时间重叠，耗时不是受控性能基准。最终浏览器新建项目→确认→方案切换→实际仿真→JSON/PDF/ZIP完成，5页PDF提取核对天气摘要与条件，旧异常项目仍禁用且返回stale/null。四个早期浏览器失败保留，最终页面脚本异常为零。

## 测试纪律与下一批

首轮天气测试发生临时目录权限错误，恢复隔离原生临时目录后记录40项旧契约失败；其中部分失败是缺少回执/定位信息，不能称为40个独立错误计算。首轮Windows全量976通过/25跳过/6子测试，但随后的Linux临时文件竞争使该版本不能发布。最终版本另建目录重跑，不覆盖首轮证据。

浏览器累计四个脚本/断言失败保留：报告链接遗漏可见箭头、导入窗口被刷新关闭、随后不存在表单的操作、错误天气按钮未禁用。其中两项暴露产品问题并修复；页面脚本异常为零不能代替这些失败记录。首次目录竞争夹具受Windows目录项stat缓存影响，另建可移植fresh-stat夹具重跑，旧日志保留。

后续优先开发真实设计日/分区负荷：新SQL已发现10条ZoneSizes和Golden设计日名称；跨气候测试仍沿用Golden设计日，不能重命名成各站设计负荷。先建立DDY/站点/模型绑定、独立稳态热平衡基准和原生定容输出核验，再增加工程交付界面。RS-07混合Agent、一般注入、跨构件净量、DWG/完整转换、图纸修复及实楼验收仍开放。达到原八维95+之前不扩大训练；整体视觉重构仍按用户顺序后置。
