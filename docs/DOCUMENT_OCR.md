# 本地文档识别与人工校正 — 2026-10-23

资料收件箱现在可以处理扫描 PDF、PNG/JPEG 和混合 PDF。使用 [RapidOCR](https://github.com/RapidAI/RapidOCR) 3.10.0（Apache-2.0）与 ONNX Runtime CPU 1.31.0；实际运行包附带 PP-OCRv6 检测/识别与方向分类模型，参数指定本地模型路径，不在处理文件时在线下载。上游代码、模型来自既有开源项目，本项目未重新训练模型，也没有集成整个 Docling/Dify 产品。

## 使用流程

1. 首页新建项目，或在项目中补充资料，拖入文件后自动分析。已标注为 `项目名称：…`、`建筑用途：…`、`项目地点：…`、`地区代码：…`、`总建筑面积：… m2` 的文字成为待审字段；英文字段名也支持。缺失项和冲突项仍需核对。
2. 点击“对照原图 · 核对 / 校正文字”，左侧原图与文字框，右侧可修改提取文字；逐行查看识别置信度。原图可单独打开大图。
3. 填写校正原因并保存。每次修订记录用户、时间、原文件哈希、页码、修订号及全文；原始 OCR、文字框和 PDF 原文字层不覆盖。字段候选及冲突重新整理。
4. 归档项目后，原文件、识别记录和修订历史一同成为待审证据；在项目资料的来源弹窗中可以重新打开原图与历史，已归档内容只读。人工校正不会自动确认工程证据，也不会生成建筑几何或启动 EnergyPlus。
5. 管理员在 `/admin` → AI / 开发者配置查看 OCR 包版本、本地模型及处理上限；用户无需填外部 API Key。

## 实际测试

原始指标和输入哈希：[results.json](benchmarks/2026-10-23-ocr/results.json)。Windows CPU 单次运行，时间包括启动独立解析进程与加载模型，不是吞吐量或客户 SLA。

| 输入 | 实际结果 | 时间 |
|---|---|---|
| 合成中文项目说明 PNG | 5/5 明确字段一致 | 3.375 秒 |
| 同图旋转 3°、轻度模糊 | 5/5 明确字段一致 | 3.438 秒 |
| 同图旋转 90° | 5/5 明确字段一致 | 3.218 秒 |
| 同图保存为无文字层扫描 PDF | 5/5 明确字段一致 | 3.500 秒 |
| RapidOCR 官方公开宣传图 | 实际读取，三处抽查标签见结果文件；没有产生建筑字段 | 2.656 秒 |
| LookHere 公开建筑资料第 6 页栅格副本 | 五处抽查房间面积文字 5/5 找到；没有推断整栋建筑面积 | 5.750 秒 |
| LookHere 原始 11 页混合 PDF | 11 页执行 OCR，保留原文字层；第 6 页抽查面积 5/5 找到 | 26.735 秒 |

公开图纸第 6 页原文字层只有 552 字符，OCR 读到 707 字符，包含图片内部的房间面积标注。抽查指标仅为这五处数值文字是否出现，并未验证房间对应关系、全部尺寸、完整 OCR 字符准确率或热模型精度。部分细小标注仍漏识、粘连（如相邻尺寸被合为一个数字串）；不能直接采用为建模尺寸。合成样本是流程测试，不是客户项目。

来源：[RapidOCR 公开样本](https://github.com/RapidAI/RapidOCR/releases/download/v1.1.0/ch_en_num.jpg)、[LookHere 公开建筑资料](https://www.lookhere.pro/download/LookHere_Sample-Document_Construction.pdf)。原件、字体、权重和截图不提交 Git；公开可读不等于取得商业再分发许可。

复跑（预先下载公开文件，指定本地中文字体）：

```powershell
.venv/Scripts/python.exe scripts/verify_document_ocr.py --font C:/Windows/Fonts/msyh.ttc --public-image <sample.jpg> --construction-pdf <construction.pdf> --artifacts <local-output-dir> --output <results.json>
```

完整后端 190 项 + 6 子测试通过；混合 PDF 最终相关复测 21 项；前端 30 项、Ruff、语法、生产构建和 OpenAPI 契约通过。新增回归覆盖真实 OCR/混合 PDF、空白图不生成字段、预览页码、超时、跨用户拒绝、CSRF、并发修订、原件篡改、原始记录不覆盖、添加资料后修订不丢失、归档只读与外发过滤。

实际浏览器在独立数据库完成扫描件上传、自动预填、两次修订和归档。为了验证版本隔离，第二次人为将合成面积从 12345.6 改为 12345.7；数据库中两版分别保留，工程复核状态仍为 pending。390px 窗口实测页面宽 390、校正窗口内容宽与可见宽均 350，原图实际加载宽 1600。正式账号与项目未用于测试。

## 资源与工程边界

- PDF 最多处理前 80 页，其中最多 20 页 OCR；其余页明确标记未处理或警告，需拆分上传。较大嵌入图（单图超过页面积 25%）会触发整页 OCR，原文字层独立保留。较小嵌图可能没有触发识别。
- 图片拒绝超过 3000 万像素，渲染/识别最长边 2400；原 PDF 按最多 2 倍缩放。细小标注可能受限，需裁剪后重新提交。
- 每份识别使用独立子进程，180 秒超时终止；预览 25 秒超时、最多两个并行预览。进程隔离不是针对敌对文件的操作系统安全沙箱。
- 校正每页最多 30000 字符、每文件最多 100 次修订；提交前版本与文件哈希双重核对。空白、损坏、模型缺失与超时不生成虚假字段。
- OCR 只整理文字，不识别任意墙体、构造和房间邻接。扫描图自动热模型、复杂 IFC 修复、客户能耗校准和持证商业软件同题验收仍未完成。
- OCR 原文、文字框与修订全文从通用 Agent 发给外部模型的工具上下文中排除。已有视觉建模接口仍遵守其独立的显式发送授权。
