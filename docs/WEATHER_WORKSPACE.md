# 气候与天气工作台 · 2026-10-21

这版把公开气象获取、数据整理、质量检查和建筑仿真天气准备接入项目。自动分析采用可复算的规则与真实数据，没有训练新的天气预测模型，也不声称能预测建筑节能率。

## 已实现与使用方法

1. 创建或进入项目，打开「气候与天气」。填写地点标注、经纬度和同一自然年内的历史日期，点击「获取并分析」。默认上一完整自然年；支持 1984 年起至昨天，近期数据可能未发布。
2. 后端实际调用 NASA POWER，获取日均／最低／最高气温、湿度、10 m 风速、太阳辐射和降水。结果绑定原始 JSON、SHA-256、请求参数、单位、时间标准、抓取时间、解析版本；相同条件复用已保存结果，显式刷新保存新记录。
3. 查看气温／辐射月图、采暖与制冷度日、月表、质量清单、自动摘要；下载逐日 CSV 和原始文件。NASA 使用 LST 本地太阳时，不能默认为 UTC+8，也不是建筑现场实测。
4. 上传自己的 EPW，或分析项目里已有的天气证据。检查逐时时序、重复、缺小时、缺测标记及常用气象字段；显示月×小时温度热图和逐时 CSV。兼容官方旧 TMY3 的 minute=0 与现代小时格式 minute=60，混用或次小时记录会被标记。
5. EPW 通过质量检查后，可登记为「待复核」证据；来源单位、许可、登记人由用户填写。到「资料」确认地点、年代和适用范围。已有文件不会重复登记；多份有效 EPW 仍触发原有冲突准入。
6. 仿真 Gate 也执行 EPW 质量检查。错误天气不能通过“已人工确认”绕过检查；日均 NASA 结果不会被转成假 EPW，不能作为逐时仿真输入。
7. 在项目助手输入“分析天气”，本地工作流读取已保存的天气分析。新增 `weather_summary` 工具也可经 MCP 读取；共 26 个内置受控工具、9 个 MCP 工具。外部 LLM 仍需自行配置 API Key；本轮没有调用外部 LLM。

界面同时更新了登录页、项目首页、项目概览、任务入口、主题色、深色模式和窄屏布局。项目卡片、资料数量、准入和运行数量来自当前项目记录；建筑插画标明为流程示意。

## 计算口径与拒绝边界

- HDD = Σ max(0, 采暖基准 − 日均温)；CDD = Σ max(0, 日均温 − 制冷基准)。默认 18°C / 26°C；NASA 获取表单可调整基准，API 的 EPW 分析也支持显式基准。度日只是气候需求指标，不直接等于建筑能耗。
- EPW 仅在一天 24 条温度完整时产生该日日均温及度日；小时 GHI 的 Wh/m² 累计换算成 kWh/m²。NASA 直接使用经校验的日尺度单位，不把 W/m²、MJ/m² 与 kWh/m² 混用。
- 年均温、年度 HDD/CDD 和全年辐射只在完整自然年／气象年且对应指标完整时显示。无效值保留为空，不插值、不写 0；月度温度、湿度、风速为有效数据均值，表格同时显示有效日数，字段缺测计数单列。
- EPW 整理日期中的 2000/2001 只是闰年／平年索引，`source_year`、`source_minute` 保留原值；典型气象年不是实际观测年。
- 质量检查范围为时间与常用温度、湿度、压力、辐射、风字段，不是完整 EPW 格式认证，也不证明测量精度、站点代表性、极端设计值或建筑适用性。
- NASA 返回错误、超时、单位变化或坐标／日期不匹配会拒绝保存；不生成备用示例。并发下载上限 2、响应上限 5 MB；EPW 上限 20 MB、一个逐时气象年。尚无商业可用性 SLA、分布式抓取队列或批量站点调度。
- 所有业务、下载均校验会话／项目权限，写操作校验 CSRF 或 Token 权限；来源文件哈希变化时旧分析和 CSV 拒绝读取。

## 公开数据与开源项目选择

| 来源／项目 | 本轮实际状态 | 适用方向 |
| --- | --- | --- |
| [NASA POWER Daily API](https://power.larc.nasa.gov/docs/services/api/temporal/daily/) | 已实际接入并联网验收 | 全球日尺度气象、辐射资料；保留 NASA POWER / NASA Langley 来源标注 |
| [Climate.OneBuilding](https://climate.onebuilding.org/) | 界面提供查找入口；下载后上传检查 | 建筑模拟 EPW / TMY；不自动猜最近站点和项目适用年 |
| [EnergyPlus EPW 字段定义](https://bigladdersoftware.com/epx/docs/9-0/auxiliary-programs/energyplus-weather-file-epw-data-dictionary.html) | 依据字段定义实现独立解析和缺测检查 | 原生仿真天气数据准备 |
| [Open-Meteo](https://open-meteo.com/en/docs/historical-weather-api) | 候选，未接入 | 后续历史／预测天气接口；[免费托管 API 限非商业使用](https://open-meteo.com/en/terms)，不能把开源代码与免费商用服务混为一谈 |
| [pvlib-python](https://github.com/pvlib/pvlib-python) | 已调研，未合并代码／安装依赖 | 光伏与辐射分析；目前没有光伏参数和验证任务，不把水平辐射冒充发电量 |
| [Ladybug Core](https://github.com/ladybug-tools/ladybug) | 已调研，未合并代码／安装依赖 | 天气与环境分析；进一步集成需逐项验证计算范围和相应许可 |

本轮新增解析代码不复制上述项目的实现，也不额外安装大型 ML 库。当前任务是数据获取和可核验分析，直接实现这些规则比训练一个无验证数据集的模型更适合。以后做建筑天气归一化或负荷预测，需要独立的实测能耗、日历、运行时段和按时间划分的训练／验证集；本轮未宣称这些预测能力完成。
