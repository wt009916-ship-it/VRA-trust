# 年度设备与用途能耗账交付（2026-11-09）

本批补齐实际设备模拟能耗的用途分项。原应用只读取各载体 Total End Uses，现可建立来源绑定的供暖、制冷、风机、水泵等14用途×5载体年度账，分别保留电力、燃气、其他燃料和区域冷热量。限定 EnergyPlus9.0.1 完整年度、原生载体与场地总量可核对的运行；不是设备选型、实测节能或合规认证。正式原型未更新，当前已核验候选仍78；本批精确提交CI完成后再按原量表复评。

## 使用及实现

项目已有成功年度运行后，在“年度设备与用途能耗账”选择运行、填写名称/分析用途，生成分项账。`extensions → end_use_records.Ledgers.source → domain.view/core.read_validated → end_use.inspect` 校验当前证据、完整原生输出和模型/天气/引擎/代码哈希。派生账另绑解析器及共享时轴版本，不改物理核心、不重写旧 manifest。原业务数据保持。

每格包含原SQL报告/表/行/列/单位/原始文本、kWh换算及显示精度的半舍入宽度。可用完整逐时J计量时另算 ΣJ/3600000，与原表舍入区间交叉核对；缺计量显示不可用，原表0.00不能冒充精确零。MTD追溯到原生设备变量，但不声称提供每台设备的独立分摊。小时计量、载体分项合计、场地总量分别核对，不相加总表和子表。

新接口为项目下 `/end-use-ledgers` 的POST/GET、`/{id}`详情和`/{id}/report.html`。历史只返回最多20条名称与游标，明确未核验；点开才取当前详情。需要会话、项目归属、写操作CSRF。来源撤回、哈希/版本变化则status=stale且summary=null，HTML撤数，前端失败/超时也撤数；慢旧响应不能覆盖新选择，5秒轮询不取消尚在10秒核验窗口内的请求。

## 独立答案与真实运行

证据在 `validation/hvac-enduse-20261109/`；输入和答案先冻结，首次失败原样保留。8个设计日受控工况不是8栋实楼：两制冷、燃气/电加热、两水泵锅炉、停机零耗、实际设备与理想系统混合。单位性能曲线及PLF=1用于隔离算术，不能外推真实部分负荷效率。

独立式：风机功率=qΔp/η；制冷电功率=(内部得热+风机功率)/COP；加热输入=[110(Ti−To)/(1.73+0.10+0.04)−内部得热−风机功率]/η；锅炉燃气功率=(负载−泵功率×电机效率)/锅炉效率。控制条件和有效范围在冻结脚本，使用Fraction先算，容差max(1 W,预期绝对值×0.5%)。原生设计日每个计量检查24小时。

首版6个PTAC模型因测试输入节点接线错误被引擎拒绝；其余两泵模型原生成功，但9.0原生名称Heating:Gas与测试器NaturalGas不匹配。修正接线后6个新运行通过；两泵直接在保留原SQL上纠正名称适配后核对通过，没有伪造原始成功或重跑无变化泵模型。泵锅炉最大功率偏差约0.707/0.946 W，均在容差内。

选取C02/H01/P02/Z01/M01延伸至8760小时，恒定合成天气只保留公共EPW日历字段，不冒充气候实测。五个年度是同批受控工况的延伸，不算额外独立物理模型。最终关键值：

## 验收与边界

- 首年度实现457项通过；修复解析异常、来源映射及前端轮询后，最终真实HTTP471项通过。主客户端108响应，另8次匿名/外账号请求；后者在server.log及checks有记录，未进入主客户端events。所有测试账户仅在隔离库，随机凭据只在内存，服务已停止。
- 后端首轮4失败/23通过：三个实现/接口缺口和一个测试器名称错；纠正后27通过，增加有界历史和实际HTTP错误协议测试后29通过。前端新增10项包含于完整225项通过，语法检查及Vite构建成功。精确提交CI在后续独立证据分支补录，当前不提前宣称通过。
- 真实引擎保留无热容/合成地理位置/泵效率低/未请求设备变量等Warning；无Severe/Fatal的最终运行才可用。污染排放因子缺失警告不能据原生零污染值称零碳，本账不输出碳结论。物理简化警告限制实楼外推，不被成功退出消除。
- 其他燃料、蒸汽及其聚合已按9.0载体映射实现，但本批未取得这些设备的独立原生非零基准；未验现场发电、变频复杂部分负荷、真实气候下效率/容量和实楼账单校准。解析阶段沿用核心校验，非独立完整资源沙箱；不宣称长期性能验收。
- 本批功能界面已接通且逻辑/构建通过，用户选择不开浏览器，因此布局、点击及可用性待验，无体验加分。没有扩大数据训练、没有整体视觉改版。

## 复现和来源

安装项目依赖及9.0.1引擎，设置ENERGYPLUS_EXE。不要覆盖历史目录：

```text
python -B scripts/verify_hvac_end_use.py --inputs validation/hvac-enduse-20261109/frozen-v2 --output NEW_DESIGN_DAY_DIRECTORY
python -B scripts/verify_hvac_enduse_annual.py --inputs REHYDRATED_ANNUAL_FROZEN_FINAL --output NEW_ANNUAL_HTTP_DIRECTORY
python -B -m pytest tests/test_end_use.py -q -p no:cacheprovider
```

年度先将 annual-frozen-final 复制到新目录，把各 weather.epw.gz 解压为 weather.epw，保持frozen.json/模型不变。脚本会核对冻结脚本、模型、天气SHA。CI的gzip原生SQL投影来自首次成功M01运行，保留6个用途计量共52560条，不是模拟生成的通过输出。完整原生SQL路径/大小/SHA在local-raw-sql-index.json；不发布运行账户库或凭据。

9.0文档依据：[ABUPS与用途表](https://bigladdersoftware.com/epx/docs/9-0/input-output-reference/output-table-summaryreports.html)、[风机](https://bigladdersoftware.com/epx/docs/9-0/input-output-reference/group-fans.html)、[水泵](https://bigladdersoftware.com/epx/docs/9-0/input-output-reference/group-pumps.html)。固定版本原生输出决定实际名称；未以25.1文档套用9.0。模型为自建受控参考，不代表制造商设备验证或工程审签。
