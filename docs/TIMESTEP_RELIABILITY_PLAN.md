# 下一能力批：同模型时间步敏感性检查

状态：计划，未实现/未验收，不预加分。接续PR67，只有它的精确CI收口后才进入实现。原目标仍八维/87项95+；公开参考开发，不扩训练，不提前整体改版。

## 为什么做

已有HT-002、FF-03独立解析证据证明部分5/10分钟输入超出既定误差限。应用目前只有“未验证时间步独立性”限制文字：`hourly_thermal.LIMITATIONS`；`Domain.compare`比较不同方案年度能耗，要求不同scheme及baseline，不能证明同一模型的时间步敏感性。不能重复跑原失败8/11题当新进展，也不能仅把时间步改为1分钟就宣布普遍可靠。

交付目标是工程师能够取得明确不同步长的模型副本、真实运行、检查仅时间步变化是否成立、查看同一时刻温度/负荷差异，并在来源变化后撤回结论。数值接近只表示本模型/本输出在声明阈值下步长敏感性较小，不是解析真值证明、一般收敛阶或实楼精度。

## 一批完整任务

1. 限定IDF9.0、显式唯一Timestep对象与原生9.0.1。不修改原输入，不自动换算法/日程/天气。生成有来源SHA和变更字段清单的副本，经现有证据审查流程后运行；不自动挑一个“安全”步长。
2. 比较2或3个同项目、成功、当前有效的真实运行。除Timestep数值外所有IDF词法字段必须一致；天气、引擎/物理代码、模拟环境与覆盖分区一致。忽略注释/空白不忽略字段。拒绝顺带改材料、算法、设点、倍数、日程、输出或模拟期间；不以面积相同或文件名相同当等价。
3. 重新读取受绑定保护的原生逐时数据，核验完整时轴。按年/月/日/小时/DST/环境对齐，不假定不同时间步SQL的TimeIndex数字相同。温度按K绝对差，负荷按W绝对差和明确分母的相对差；近零时相对值null。分别报告全时段最大差、峰值大小/时刻变化、期间积分差；不让年度抵消掩盖逐时差异。
4. 可选显潜热只在两边均完整具备PR67原生变量时比较；未覆盖内容明确列出，不能暗中只比显热后宣布总负荷稳定。范围限定已声明理想设备，不推算设备效率。
5. 用户明确声明判断阈值及用途；阈值没有“规范默认值”。每对结果只给不适用/资料不一致/差异超限/声明阈值内，3步长也不能自动宣称Richardson收敛或精度达标。原粗步长独立误差问题不能靠两次数值接近关闭。
6. API、同源报告、功能界面连通；来源撤证/代码或原始文件变化清空当前判断。浏览器依用户决定继续待验，不能算UX通过。

## 预先冻结的退出门槛

- 实现之前冻结新几何/边界/热容量/日程及独立答案；不复用HT/FF旧数值题作未见样本。至少包含恒定条件、受控自由漂移、周期热响应，以及故意只改时间步以外参数的拒绝对照。独立答案须有物理前提及不读取原生结果的计算方法。
- 显式构造相同年度总量却逐时错配、峰值异时、近零分母、DST/闰年/漏小时、跨项目/撤证/迟到结果等反例；拒绝逻辑不能只靠JSON假成功。新真实原生运行+认证HTTP全过程留原始结果。
- 功能正确性与独立真值准确性分开：若新原生值超出事先误差门槛，保留失败，不改容差；应用必须能正确展示差异或拒绝不一致证据。不能因检查工具自身工作就给动态物理准确性满分。
- 最终仅运行该产品提交一次完整CI；已通过的专项不无变化重复。报告记录工程价值/剩余边界及原子项评分归属，是否提分由证据决定，不能预承诺。
