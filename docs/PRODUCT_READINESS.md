# 距离工程师独立交付还缺什么

评估日期：2026-10-26。依据为活动代码、已保存的软件实跑和本轮补充的多样本验收；下面的目标数字是建议的试点门槛，不是已完成成绩或行业认证标准。

## 当前判断

当前是可运行的工程预览版，适合合作工程师主持的受控试点。距离让陌生工程师安装后独立完成复杂项目、签署成果并向客户交付，仍有工程适用性、验证和组织流程上的缺口。

新增6份公开建筑IFC整模均未通过，3份的明确局部楼层完成假设情景全年计算。尤其De Zalmhaven高层有64个楼层对象、2,897墙体但没有IfcSpace，当前无法从构件自动恢复房间；台北101风模型为未支持的RWIND格式。这说明复杂工程输入覆盖仍是首要瓶颈，本轮增加引擎预检只修复了“提前识别失败”，没有完成复杂建模能力。详见[实测表](MULTI_PROJECT_ACCEPTANCE.md)。

产品主线应始终是：**既有公共建筑资料不完整时，形成可追溯的改造决策，明确哪些结论可用、哪些必须补证。** 图纸识别提供候选，三维帮助复核，AI 调用工具，EnergyPlus 计算物理情景；最终交付是有来源、范围、取舍和责任人的工程成果。

稀土应用是需要材料与现场证据支持的业务方向。当前还没有证据证明某种稀土方案在客户建筑中取得节能优势；继续扩展登录或接入更多聊天框架，不能替代这部分验证。

## 差异化如何成立

“AI + 3D + EnergyPlus + API”不能单独证明壁垒。[Honeybee](https://www.ladybug.tools/honeybee.html)已有建模、EnergyPlus/OpenStudio和多种性能分析；[广联达BIM设计协同平台](https://www.glodon.com/product/411)官方也列有校审、交付、项目管理和开放API。这些是厂商能力说明，未在本项目中进行同版本授权实测，不能据此制作速度或精度排名。

本项目较清晰的产品方向是把**残缺资料、材料依据、计算结果、失效追踪、补证优先级和有限域方案取舍**放在同一条工程责任链中。目前可以展示这条链的限定实现；能否让工程师减少返工、提高交付质量，以及客户是否愿意付费，需要试点数据证明。稀土材料在这条链上的真实验证比持续增加通用Agent框架更接近最初目标。

## 样本与准确度应怎样验证

以前的几何验收集中在Duplex、Esplanades和诊所，反复跑同一建筑主要证明回归稳定，不能说明新项目覆盖。本轮新增独立输入的完整结果见 [多样本验收](MULTI_PROJECT_ACCEPTANCE.md)。同一栋楼的不同楼层、导出版本、气象或参数情景不重复计算独立建筑数量，控制几何与客户项目分别记录。

后续每批验证应先固定样本、来源、版本和验收条件，再测试；至少保留一组未参与修复的输入作为留出集。对每份资料分别记录：上传、提取、空间保留、复核工作量、严格热边界、假设情景、引擎计算、报告可用性。失败的样本仍进入结果表，不能用只展示成功案例的比例代替覆盖率。

原生全年成功、零Warning或与同一引擎CLI相同，只能说明对应软件路径或封装；客户建筑预测误差还需可靠实测和适用模型。[ASHRAE对验证方法的说明](https://handbook.ashrae.org/handbooks/f17/IP/F17_Ch19/f17_ch19_ip.aspx)区分实证验证、解析验证和相互比较；引擎的验证不自动覆盖本应用的图纸翻译和工程假设。

## 从预览到可交付的三个门槛

以下为建议的工作范围，尚未通过，不承诺未经验证的工期或成熟度百分比。

1. **工程闭环试点。** 取得至少3个独立且授权的目标建筑，含不同规模/资料质量；2位工程师按原图和项目依据核对。每个试点交付来源/缺项清单、复核模型、基准与候选、报告和计算包；必须记录失败、人工工时和必要的回源操作。复杂输入达不到目标时先缩小明确适用场景。
2. **客户结果可用。** 至少一个项目具有足够周期的分能源账单、设备和运行资料，按预定标准校准并留出验证；有一套真实材料对照证据。有条件时用合法可用的商业软件按相同输入/范围/指标对照，无法等价的假设先标明。由工程师完成校核、业主检查输出是否回答投资与风险问题。
3. **受控商业交付。** 在独立环境完成身份、安装、升级回滚、配额、备份恢复与容量验收；完成软件/数据授权方案、产品手册、支持约定和版本管理，再讨论扩大交付。公网与第二台电脑部署仍遵循用户此前暂缓指示。

下一轮优先围绕输入覆盖、工程真值和报告闭环推进。已有MFA、数据库、API等基础能力继续回归，工程主线不再被基础设施扩展挤到后面。
