# 自由漂移温度与分区时序交付

本批为开发侧可重复验收，不是第三方工程认证。继续原八维 95+ 目标，当前仍为 76 分；未扩大训练，整体视觉改版仍按用户指定顺序后置。

## 实际增量

逐时结果面板新增分区选择、两个全楼峰值日的室内空气温度曲线和逐时数值表。温度使用原生 SQL 经现有解析器核验后的数据，不乘分区倍率；缺测不补零、不插值。纵轴标明自动缩放，恒温与零温也能显示；明确峰值日不一定包含分区全年极值、空气温度不等于操作温度，不自动给出舒适性达标结论。

新增可重放脚本 `scripts/verify_freefloat_thermal.py`，采用独立非线性空气能量守恒答案，真实调用固定 EnergyPlus 9.0.1。冻结输入与答案在 `validation/freefloat-thermal-20261107/native-inputs`，Windows 与 UID 65534 Linux 使用相同字节。每平台 8 个模型：6 达到 0.02 K 预设容差，5/10 分钟两例超限；并非全通过。脚本退出码表示批次执行完成，是否达标必须检查 receipt 的 `all_cases_passed` 和各项 `status`。

## 验收证据

- 双平台温度及显热序列最大差 0；零 HVAC 交付及湿度前提通过。独立方法与失败过程详 [交叉验证](FREEFLOAT_THERMAL_CROSSCHECK.md)。
- 92 项前端测试、前端语法检查和构建通过；66 项逐时解析/API/契约回归通过。前端构建保留 Three.js 大分块提示；回归保留 Starlette/httpx 弃用提示。未把上批全量统计当本批新运行。
- 新隔离数据库中真实参考模型年度仿真 1 次，6 区、8760 小时。浏览器逐个切换全部 6 区，12 条曲线各 24 点、288 个显示温度与 API 一致；390px 页面宽度无溢出；撤回模型确认后 API 为 stale/metrics=null，温度面板自动移除；页面异常 0。报告 JSON 中的原生模型/SQL 哈希保留。
- 普通鼠标稳定性等待及截图超时，未计视觉通过。第一次注册脚本已经完成注册，却等待不存在的旧按钮名称而失败；保留日志，未重复注册覆盖。
- 后端 68 个 Python 文件与基线提交逐字节相同，因此没有物理版本改变；未改写旧 manifest，原有 174 条业务记录、3 条任务及参考索引保持相同哈希。用户的 SKILL.md 未提交编辑保留。

证据文件和源码版本见 [索引](FREEFLOAT_THERMAL_EVIDENCE.json)。GitHub CI、合并及原型更新以本批 `release-receipt.json` 为最终发布回执；本文的功能验收不替代发布检查。
