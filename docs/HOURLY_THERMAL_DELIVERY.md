# 逐时热工补强交付记录

本批在 `feature/dynamic-thermal-20261107` 实现；发布状态以本批 release 回执为准。目标仍为原八维95+，本记录不代表目标已达到。

## 应用变化

`backend/hourly_thermal.py` 读取实际 EnergyPlus 9.0.1 SQLite 的逐时分区空气温度、采暖显热交付率、制冷显热交付率。明确检查版本、环境、变量字典、W/C单位、平均值类型、时钟顺序、60分钟间隔、全年/设计日完整覆盖、全模型分区和有限数值。不修改上传模型，不把未请求或不支持的数据补成零。

负荷应用分区/分组倍率一次；温度保持原值。全楼峰值由相同时刻分区负荷相加后取最大值。输出分区温度范围、各自峰值、显热交付量、全楼同时峰值以及两个峰值日的24小时曲线。完整原生时序留在SQL，JSON中没有假装展示全年曲线。

`core.py` 将新解析器纳入物理版本，运行结果绑定模型、SQL和解析器哈希；旧版本不改写。现有授权的运行/报告接口统一承载结果，前端、HTML、PDF和证据ZIP同源。没有新增绕过项目归属的下载入口。小时平均负荷、设计容量、电耗和含潜热总负荷分别说明。

图纸重新处理表单中，空手动角度校验移入公共错误处理。实际浏览器复验见 `browser-empty-angle-v1.log`：可见错误、零POST、零新增记录、无未捕获异常，原件下载SHA一致。

- 36项解析与恶意数据测试通过；89项前端测试及构建通过。完整后端Windows1119通过/25跳过，Linux1128通过/16跳过，各6子测试通过；见 `candidate-checks-v1.json`、`linux-checks-v1.json` 及对应完整日志。
- 浏览器通过真实页面创建参考项目、复核输入、提交真实仿真、显示逐时图表。`browser-hourly-v2.log` 验证6分区/8760小时、四条24点曲线、峰值与API一致、JSON同源、HTML来源哈希、实际PDF，以及390像素页面无整体横向溢出。
