# 本批缺陷与复现

所有模型例子来自26e8ca0、固定9B、实际HTTP任务；路径前缀为validation/agent-output-contract-20261113。历史原始输出不覆盖。

## OC-01 用户所问指标可被模型改写：显式路径已修复，自由路径仍开放
- 功能：读取计划与数值交付。
- 描述：此前用户只能选择记录，合法来源数字仍可能不是所问指标。
- 复现：选择热工总R/面积解释，让模型提案U或在交付阶段提交来源真实的材料层R。
- 预期：拒绝替代，不将其计作用户选定产物。
- 实际：本版提案更换/漏项/扩项拒绝；越出显式合同的数值交付终止，answer=null且无已核验数值。真实C01–C03遵守选择。没有显式合同的自由意图仍未由应用完整核验。
- 严重程度：高，显式路径已修复；开放语义未关闭。
- 证据：test_agent_explicit_outputs.py；backend-second.log、backend-followup.log；live-first/C01–C03-task.json。
- 建议：继续绑定原问题要求、冻结模型计划和当前读取回执；不得将用户勾选计成自主理解。

## OC-02 能耗交付字段说明与执行要求不同步：本批修复
- 功能：直接模型数值交付。
- 描述：PR72 E09/E13漏抄energy_context，而旧说明未列该字段。
- 复现：读取能耗记录后检查下一轮professional_deliver工具schema及模型返回。
- 预期：能耗候选要求完整上下文；同数值错年份/载体不能通过。
- 实际：说明从Statement生成；纯能耗候选schema要求非空energy_context；D01–D04最终结构化交付都带正确上下文。混合专业场景仍由执行校验守住边界，未宣称混合模型全验。
- 严重程度：高，本批限定路径已修复。
- 证据：test_energy_delivery_schema_requires_context_after_actual_read；model-call-006/010/014/018；assessment.json。
- 建议：后续使用当前已读事实回执减少模型重复抄写；保留现有来源重验，不能用宽松字段默认值掩盖错误。

## OC-03 仅取得目录就虚构正式交付：未修复
- 功能：直接读取、原文诚实性。
- 描述：目录未选择数值事实时，模型将未读取当成null，并推断年数与面积。
- 复现：运行冻结D02，问题为室内照明电能量；首次end_use_read不含fact_keys。
- 预期：继续按目录选择并读取事实，不能输出数值、缺失结论或称正式交付。
- 实际：model-call-008称null kWh、study_years=1、area=25并称正式交付。后续正确读到0，正式结构化交付的年数/面积均null。应用没有接受错误原文，但模型关键错误真实存在。
- 严重程度：高/关键验收失败，阻止本批提分。
- 证据：live-first/model-calls/model-call-008.json、010.json及D02-task.json。
- 建议：明确目录/数值/交付阶段，以可验证的受限工具输出推进任务；最终状态只能由当前交付回执决定。原文保留审计，不能靠隐藏或免责声明认定模型正确。

## OC-04 无显式指标路径额外交付未要求的账单总量：未修复
- 功能：自主读取指标范围。
- 复现：冻结D04只要求模拟能量总和及期间载体。
- 预期：仅交付native_total_kwh及对应上下文。
- 实际：模型读取全部8字段，最终同时交付native_total_kwh与bill_total_kwh。两个值及年份均正确，但超出冻结问题范围。
- 严重程度：中；功能范围失败，不是跨项目安全越权。
- 证据：live-first/model-calls/model-call-017.json、018.json；D04-task.json。
- 建议：自主路径也需要可审查的指标计划和逐项交付范围；不能仅靠记录ID权限保证问题正确。

## OC-05 期间解释出现原始字典：代码修复，视觉待验
- 功能：能耗解释阅读。
- 复现：请求期间解释；此前返回str(energy_context)。
- 预期：原始账期与模拟期间明确且易读，不泄漏原始字典格式。
- 实际：C01明确展示两期间、原生年度及映射规则；逻辑测试不含字典花括号。浏览器按用户选择未验收。
- 严重程度：低；代码路径已修复，不能据此加体验分。
- 证据：period-final.log、live-first/C01-task.json。
- 建议：后续有条件时完成真实界面阅读和响应式验收。

## OC-06 凭证澄清未明确区分不存在的输出能力：风险保留
- 功能：能力边界与澄清。
- 复现：冻结F02要求签发节能凭证数量。
- 预期：不以误差统计替代凭证，不暗示声明一个阈值即可签发。
- 实际：没有数值替代，符合冻结的“无数值+澄清”条件；但澄清举例误差阈值/覆盖期间，尚不足以说明签发能力边界。先两次计划错误再恢复。
- 严重程度：中；本次没有宣称认证通过或发证，不能将此风险改判为已经发证。
- 证据：model-call-020/021/022、F02-task.json。
- 建议：将已实现能力目录与澄清理由关联，区分指标缺失、输入欠缺和应用不支持；不能将补输入当成解锁不支持能力。
