# 选定 IFC 构件几何并集交付

当前候选实现：用户在同一已读取 IFC 中明确选择 2–64 个物理构件，真实原生网格计算体积和、几何并集体积及重叠重复扣除量。开洞沿用原 IFC，单独洞口/特征、空间对象不能混入选择。结果不是材料净用量或专业计价认证；混合材料交叠归属、施工计量扣减规则仍未实现。

通过既有文件系统/网络隔离及资源预算运行固定版本 manifold3d 3.5.4 的 Mesh64 并集。每个操作数先经过既有拓扑检查，输出再次做独立边界积分/拓扑检查，并校验并集不超出体积和、不小于最大操作数。输入面数上限20000、输出面数40000；超预算、缺网格、不一致均保留未知，不用体积和冒充并集。仅做已核验壳体的整体方向归一，不自动补洞或容差焊接。依赖来源为[Manifold 官方仓库](https://github.com/elalish/manifold)，许可证及固定 wheel 哈希保存在验收目录，库的宣传不作为产品正确性证明。

新增项目归属/CSRF保护的 /ifc-unions 创建、历史、当前JSON及HTML报告。不可变记录绑定原文件哈希、读取记录哈希、所选实体和解析器版本；输入/版本变化后结果为stale/null。计算过程中再次核查来源，发生变化不保存成功记录。界面显式多选、按记录显示真实选择范围；5秒刷新并撤下失效并集数量。微小非零体积以科学记数显示，避免格式化为零。

## 验证边界

- 30项专项最终通过。前两轮分别3个/1个大坐标旋转及相接面案例失败；先消去共同原点、再采用共同正交基计算，保持原容差后通过。
- 100项前端测试、构建和语法/静态检查通过；既有Three.js大分块提示保留。
- Windows/Linux同字节基础9例：8个数值交付，沿边接触1例因输出拓扑未核验而未知，不能算9例数量能力全部通过。
- 扩展6例双平台通过：不同构件方向、三维嵌套、非均匀缩放、厘米单位、镜像及圆柱交叠。圆柱解析20.219262434283316m³，网格约20.20826374758486m³，误差约0.011m³；预设容差0.02m³，限定曲面近似。
- 公开Duplex原始STEP/Decimal独立解析49个轴向矩形棱柱，抽取6对实际计算，双平台6/6在1e-8m³内一致。3对无重叠、3对只有原始小数导致的极微小交叠；此子集没有大于1e-8m³的重叠，不能替代合成实质重叠验证。
- 真实无头浏览器3文件：48/36/12、46/24/22三口径及边接触未知；JSON/HTML、原件哈希、匿名报告401、390px无横向溢出通过，截图已实际查看。一次控件定位超时和一次相对URL错误保留；复用既有记录后核验，没有重复上传或覆盖。
- 隔离合成文件临时损坏后，页面轮询撤下数量并禁用计算，API为stale/null；原件备份后逐字节恢复。此测试不影响原业务数据，也不声称验证全部CAD历史页面的自动刷新。
- Linux第一轮完整回归1190通过/1失败/22跳过/6子测试：已结束进程在读取/proc前被回收，测试竞态。只捕获FileNotFoundError并仍拒绝活跃进程，重新完整运行。候选v1/v2唯一差异为tests/test_execution.py，应用源码一致。最终Windows1182通过/31跳过、Linux1191通过/22跳过，均6子测试通过、2个既有警告；每平台6项年度参考依赖检查跳过，其余主要为跨平台专用检查。发布以release-receipt.json为准。
