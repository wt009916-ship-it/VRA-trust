# IFC 开洞与关系完整性修复

本批修复一个已由真实隔离 API 复现的工程量错误：2×3×4 m 宿主被洞口完全覆盖时，旧路径仍交付 24 m³。当前显式关闭二维布尔捷径，空网格保持 volume=null；不猜测为已认证零值。原生设置的含义参考 [IfcOpenShell 几何设置](https://docs.ifcopenshell.org/ifcopenshell/geometry_settings#boolean-attempt-2d)，实际行为以本批固定环境实验为证，不泛称所有三维布尔运算正确。

新增有预算的开洞关系检查：同一洞口重复绑定、关联多个宿主、缺失宿主关系时，保留关系实体 ID、宿主与洞口 ID、问题原因，相关对象不交付几何量。正常多洞口不按名称或形状擅自合并。检查最多 20000 条开洞关系，原件不修改。解析器版本自然变化，旧读取记录保守失效，不重写历史哈希。

界面新增空网格未知说明和开洞关系定位。体积仍是单构件近似几何量；跨构件重叠并集及专业计量扣减规则尚未实现。完整声明工程量与几何量继续分列。

## 实际验证

- Windows 1152 通过 / 31 跳过；非 root Linux 1161 通过 / 22 跳过；均 6 子测试通过、2 个既有依赖警告。物理源码未修改，本批未重跑年度参考；每平台 6 项年度参考依赖检查跳过，其余主要为另一平台专用检查，详日志。
- 37 项 IFC 专项通过，其中新增 4 项米/毫米 × 全覆盖/普通穿洞 API 案例及 3 项关系歧义案例。96 前端测试、构建和代码检查通过；Three.js 大分块提示保留。
- 双平台同字节 8 案例：6 个数值与独立几何答案一致，1 个全覆盖空网格拒绝，1 个重复关系拒绝。不是 8 个均算出正确体积。
- 公开 Duplex 模型双平台各 108 个棱柱、21 项声明面积、295 条空间关系核对一致。唯一跨版本几何状态变化为 #5903，从未知变为约 0.659913616 m³；额外原始 STEP / Decimal 交集答案核对通过，误差约 1.06e-14 m³，预设容差 1e-10 m³。173 个取得近似量的构件中仅上述 109 个有独立数量金标准，不默认其余通过。
- Windows 新增旋转37度、嵌套旋转、非均匀映射三个开洞模型，体积分别约22、22、528 m³，均在1e-8 m³误差内。重叠聚合反例的数学并集为24 m³，产品聚合结果仍为null，记录为能力未实现。
- 无头真实浏览器完成3文件上传、构件切换、未知/歧义/22 m³显示、JSON核对、原件下载哈希、匿名401。390px页面无横向溢出。两张缺口详情截图已检查，可读拒绝原因和实体定位；截图存在固定导航覆盖局部标题的情况，不能称完整视觉或阅读舒适度验收通过。GUI Chrome启动失败保留，无头结果不能代替GUI环境稳定性。
- 浏览器首个脚本误要求固定小数位22.000000而失败；实际产品显示22，随后复核已保存的三条记录，没有重复上传覆盖。原件与失败日志保留。

代码、证据索引与本批发布状态分别以仓库提交、IFC_OPENINGS_EVIDENCE.json 和 release-receipt.json 为准。文档不代替远端CI/原型切换验收。开发侧评分仍76，95+未达。
