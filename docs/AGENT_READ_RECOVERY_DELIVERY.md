# 已选记录的失败恢复与任务范围实验

应用提交：`bdd0551b3855b82769038b37cb2bcdf4c0804d90`。本批评分维持 **75/100**，目标仍为有证据支撑的95+。使用隔离数据库、合成工程参数及固定公开预训练模型，没有扩大训练，没有真实楼宇校准或专业认证。

## 实现范围

- 单条与批量读取在结果读取前检查记录和项目归属。批量遇到缺失编号时检查完整批次，分别返回存在/不可用编号；存在只是元数据，不是已经读取的数值。
- 只有直接记录查找失败才产生类型化缺失错误。服务内部字段错误不能被当作记录不存在；跨项目与计算授权错误仍直接拒绝，不交付部分结果。
- 对当前问题/历史允许引用的编号给出逐项缺失核验建议；对模型猜出的编号仅建议查询目录。建议本身不会执行工具、补零、重试计算或增加权限。
- 记录已选但未正式交付的目标。一项回执不能消除其他目标；最终答复、失败任务和界面保留未交付编号。历史查看重新核验事实，原任务版本不改写。
- 保持5轮模型响应、15事件和最多2次可恢复失败。计数包括批量的实际子操作；没有隐藏调用或放宽预算。

这张清单只跟踪模型实际选择过的读取目标。它不能证明自由问题被完整理解，也不能发现所有从未选择的子任务。缺失回执只是当前项目的可用性核查，不是工程计算完成。

### 独立任务拆解实验

另对每个模型进行8次单轮范围提议：2道已见问题、6道新问题。只给问题与固定schema，预期范围不发送给模型，不执行提议中的任何工程工具。该实验不能与应用任务完成率合并。

判分器首次缺少可选的`jsonschema`库，已保留原始失败与实际模型响应。后处理使用环境现有Pydantic按同一字段约束严格核验，再对照冻结预期范围和逐字来源引用；不重调模型、不改写响应。严格匹配4B为3/8（已见0/2、新题3/6），8B为4/8（已见1/2、新题3/6）。人工检查还区分引用文字是否真正支持相应子任务。

判题限制：P02碳信用被归入standards而预设为lifecycle、P05面积矛盾被归入simulation而预设为other，存在分类设计歧义；保留冻结规则的失败，但不能全部解释成实质理解错误。更明确的错误是两模型C01遗漏运维、4B C02改写来源引用中的编号、4B P03遗漏设备、8B P01把明确不要检查的梁纳入范围。4B P02还违反一次范围提交的协议。没有为了提高结果在测试后修改答案。

目前证据不足以将模型提议直接用作可靠完整任务范围或执行授权。下一步采用显式可追溯的任务范围与逐项交付状态，模型草案仍需保留未验证覆盖标识；随后推进复杂文件和气候/设计工况基准，避免反复调同题提示词。

## 缺陷与修复记录

### RR-01：缺失读取错误没有逐项恢复信息（已修限定范围）

- 对应功能：单条/批量专业记录读取。
- 问题描述：首个不可用编号导致整批退出，模型不知道其余目标是否存在或该如何安全恢复。
- 复现步骤：在隔离项目请求读取两个不存在的明确编号；或将不存在的成本编号与实际热工记录组成批次。
- 预期结果：不交付部分数值，列出整批存在/不可用目标，给出不执行的安全后续调用建议。
- 实际结果：修改前3项新增复现失败；修改后类型化错误包含完整编号范围及`result_reads_executed=0`，存在记录另读后才交付。
- 严重程度：高，影响任务真实性与失败恢复。
- 证据：`before.log`；`tests/test_agent_read_recovery.py`；两模型回归C02、新题D01。
- 修复建议：已实现类型化错误和完整预检；继续验证新增工具及目录竞态，不将所有KeyError归类为缺失。

### RR-02：一项交付提前结束，其他已选目标丢失（已修限定范围）

- 对应功能：Agent完成控制、历史查看、界面。
- 问题描述：一项缺失回执的finish请求可能结束仍有其他已选目标的任务。
- 复现步骤：批量选择两个缺失编号，只提交第一项finish回执，随后返回“已完成”文字。
- 预期结果：保留另一目标并在剩余原预算内提醒；文字不能变成完成证据。
- 实际结果：专项验证补齐第二项后清单清空；仍未交付时最终/历史清单保留，流程不标为整个工程任务完成，原任务版本不变。
- 严重程度：高。
- 证据：`test_one_absence_delivery_does_not_erase_other_selected_missing_target`、`test_final_and_history_keep_undelivered_selected_target`及前端转义测试。
- 修复建议：已修已选读取目标；从未选择的自由问题子任务仍属RR-03。

### RR-03：未查询子任务仍可遗漏（开放，延续MR-05/08）

- 对应功能：自由问题理解、多专业任务完成。
- 问题描述：读取恢复不能补回模型最初没有纳入工具范围的子任务。
- 复现步骤：运行冻结N02（梁结果加碳/运维）或C01（指定梁编号加设备目录）问题。
- 预期结果：各要求独立查询并正式交付；未查询不能推断完成或缺失。
- 实际结果：两模型仍失败；局部正确数值或一个编号回执不能满足整个问题。原始文字的具体错误保留在真实响应中。
- 严重程度：高，95+门槛未通过。
- 证据：本批两模型`regression-*/results.json`及逐次`model-call-*.json`，公开基准摘要。
- 修复建议：明确请求范围、来源引用和逐项交付状态；把范围未验证作为独立状态，不依靠增加提示或隐藏失败来消除扣分。

### RR-04：交付真实但未请求的其他记录（开放）

- 对应功能：读取范围语义。
- 问题描述：数值与来源一致不代表回答了用户要求的编号。
- 复现步骤：4B运行N01，项目中存在一个梁，但用户只要求另一个指定编号的可用性。
- 预期结果：只核验指定编号，不交付其他梁的数值。
- 实际结果：指定编号缺失回执之外，模型继续读取并正式交付其他梁结果；该题按预设`no_facts`规则失败。
- 严重程度：高，任务范围正确性缺陷；不是计算公式误差。
- 证据：本批4B N01事件与原始响应。
- 修复建议：将结构化请求范围绑定到最终交付校验；避免把“目录里有记录”当作用户要求其结果。

### RR-05：模型生成范围草案本身不可靠（开放，实验发现）

- 对应功能：拟引入的任务拆解，尚未接入应用执行。
- 问题描述：模型可能漏子任务、违反一次提交的协议，或改写所引原文。
- 复现步骤：固定`frozen-scope.json`，分别用固定4B/8B进行一次`propose_scope`推理。
- 预期结果：恰好覆盖各实际请求，排除否定目标，引用逐字正确；草案不产生计算授权。
- 实际结果：失败原始响应及修正判分结果单独保留；不得将该实验写成应用任务完成。
- 严重程度：高（若直接接入执行）；当前仅实验。
- 证据：`scope-*/results.json`、`scope-*-reassessment.json`。
- 修复建议：接入前验证结构、引用及范围；完整理解不默认通过；不能因单次规划成功自动信任所有后续任务。

### RR-06：实验判分依赖缺失（测试设施，已重新判读）

- 对应功能：单轮拆解实验判分器。
- 问题描述：原实验工具在真实推理之后导入未安装的`jsonschema`，不能完成自动判分。
- 复现步骤：在现有虚拟环境运行首次scope实验。
- 预期结果：推理前验证判分器依赖；判分设施错误与模型错误分开。
- 实际结果：原始回执含ModuleNotFoundError；模型原始响应完整，后处理严格校验并关联原文件SHA256，不重跑或重写原始结果。
- 严重程度：中，影响测试结论可信度；未进入产品代码。
- 证据：scope原始回执、`assess_scope.py`与重新判读文件。
- 修复建议：后续实验在首次推理前以离线固定响应自检判分器；继续固定并保存预期答案。

### RR-07：目录缺失被过度解释为未创建/未执行（开放，延续MR-07）

- 对应功能：模型自由解释。
- 问题描述：当前项目目录为空不证明从未计算、没有历史副作用，或其他系统中不存在记录。
- 复现步骤：8B运行R01拒绝实际碳计算后续R02；另检查R03/M04/N03原始文字。
- 预期结果：只说明核验时项目目录中的可用性，不推断未执行或全系统不存在。
- 实际结果：R02原文仍称“尚未进行阶段碳计算或相关数据未被存储”；其他题把缺失解释为未创建。正式卡片只保留范围核验，不能据此判定模型原文正确。
- 严重程度：高。
- 证据：`regression-8b/model-call-004.json`及本批公开原始响应。
- 修复建议：继续隔离模型原文与核验结果，测试执行历史与记录可用性的独立语义，不以输出隐藏冒充幻觉修复。

## 2026-11-08 模型服务中断后的同任务恢复（新候选）
