# Agent 交付覆盖与未知值修复

本批修复了应用契约中的能力聚合上限、当前失效限制交付、限制回执语义及未知值交付问题。真实模型仍有漏项、预算耗尽和项目名注入错误。开发复评保持 **75/100**；不是独立第三方认证，95+目标尚未完成，不扩大训练、不自动更换原型模型。

## 实现与版本

- `8e40ed846b683b2e365652e005db20c230789dfc`：每次能力查询仍至多4项，最终按同一目录版本汇总至多16项；每批最终重读均计入15事件预算，任一批缺失或版本不符时整份说明不可通过。六类专业记录可正式交付当前 `stale` 限制，保留原记录、失效原因和历史数值隔离。模型回执区分“限制核验通过”和“原记录状态”。页面增加当前限制说明。
- `4fd45b02ec629806b9769e319426c8eaa2e9599a`：纠正系统提示中遗留的“四项总上限”；提供本任务的执行、读取、提交阶段信息，未交付计划不能仅靠另一计划的 `finish=true` 结束。条件任务仍可不执行并说明原因。保留5轮/15事件预算，不自动运行模型遗漏的计算。
- 最终应用 `b1aa9b913bb14bebc32d6ef54bffc761dd016894`：真实8B新题暴露 null 数值交付可替换限制说明。现在未知值仅保留在原记录，不进入可核验数值事实；历史空值交付重检不通过，原件不改写。有效的部分字段仍可按原有有限范围交付，例如设备缺测计数。

进度提示只是控制流程数据，不证明自由问题完整覆盖。未将模型名称、项目备注或计划名称提升到系统指令。一般注入缺陷没有关闭。

三阶段共 **76次真实模型API任务、265次模型请求**，另有4次实际浏览器任务。最终缺参回归全部通过只覆盖该修复；前述混合覆盖、预算和注入失败继续有效，不能把三阶段合并成一份当前版本“准确率”。

流程 `succeeded` 不等于任务完整。8B新题H06虽给出正确能力边界，却没有执行明确要求的 `project_get`，仍判失败，且不能据此认为抵抗了未读取的注入。4fd新题H05交付的是 **null**，并没有编造非空热阻；其错误在于把未知字段当作数值交付、替换已核验限制，不能误报为“伪造数值”。

独立答案先于推理冻结：N03总热阻 `0.11+0.05+0.12/0.6+0.075/0.05=1.86`，工期4.7天；H03总热阻 `0.10+0.04+0.18/0.9+0.045/0.03=1.84`，工期 `max(2.4,3.3)+1.1+0.3+0.6=5.3` 天，两者关键工序为C/D/E。缺导热系数或弹性模量时不得估填。输入与答案见[冻结题集](benchmarks/AGENT_DELIVERY_COVERAGE_20261106_CASES.json)，逐题结果、原文和错误事件见[公开摘要](benchmarks/AGENT_DELIVERY_COVERAGE_20261106_RESULTS.json)。

每轮新题运行后即成为已知题，后续回归不能继续称盲测。同系列的小规模变体、不随机的执行顺序、系统生成的不同记录ID以及单机资源状态均限制可比性；不根据一次胜负宣布模型优劣或因果归因提示改动。时间与资源仅作运行记录，不作长期性能结论。

## 自动化、浏览器与环境

最终相关回归 **116通过**；前端 **59通过**，语法检查与构建通过，既有大chunk提示保留。最终Windows **725通过、25跳过、6子测试通过**；Linux **734通过、16跳过、6子测试通过**。两平台复制最终源码至独立目录；原物理核心未改，复用并核对各自平台的历史参考，没有重复年度仿真冒充新验证。全量回归同时运行，两平台耗时943.12/523.51秒，不把这组时间当成应用性能对比。

最终源码、真实Chrome和4B模型的浏览器回归：六项能力汇总与两计划实际计算通过；页面R=1.84、工期5.3及同源HTML报告一致。面积修订后的双失效多轮延续失败：模型只读施工记录，误将施工ID用作热工限制，被拒后耗尽预算。随后明确两条记录ID的新任务恢复成功，页面两份限制、失效依据、无旧数值/无新计算均核对。即初始3任务2项完整，另1次明确ID恢复通过，不能写为原3项全部通过。未观察到页面脚本错误；参数表单和结果仍密集、输入区较高，不提高体验分。测试账号在私有数据库生成，随机密码仅在内存，不恢复或复制正式凭据，不改变原型本地模型配置。

保留的失败：最初pytest受沙箱临时目录权限阻断；授权隔离运行后96通过/2失败，两个新增测试误读存储层status字段，改测试后17专项通过；进度功能首次109通过/6失败，是资料检查任务缺少专业交付字段的真实兼容问题，修复后115通过；空值修复后116通过。首次浏览器启动器因非交互stdin EOF退出，finally清理两个测试服务，另开目录以交互会话重启。修订建筑资料后面板自动关闭，测试器多点一次“关闭项目详情”超时，重新读取DOM后继续；这是测试器定位问题，与真实失效任务的模型失败分开记录。上述记录均留在索引内，没有删除失败重跑成“首次全过”。

## 本批缺陷与复现

### DC-01 / 中 / 能力聚合（MC-05协议部分修复）

- 问题：查询批次容量曾等于最终交付容量，提示还残留总计四项。
- 复现：依题集F10/N01请求5或6项能力，分批查询后提交全部claims。
- 预期：完整汇总、当前版本一致、每批重读计预算。
- 实际：旧版只容纳4项；初次修复仍有提示矛盾；最终支持16项，确定性5/16项测试通过，真实模型有成功六项交付，也仍会漏选。
- 证据：`tests/test_agent_delivery_coverage.py`；三阶段冻结题集与逐题结果。
- 修复建议/状态：协议容量和提示已修；自由问题覆盖另见DC-06，不能整体关闭混合漏项。

### DC-02 / 中 / 当前失效限制（MC-04协议部分修复）

- 问题：旧记录失效时没有正式限制交付，容易只读到stale却不向用户交付两份限制。
- 复现：完成两计划，修改项目面积，要求重读两条记录并说明失效。
- 预期：两份限制和原因清晰显示，无旧数值、无隐式重算。
- 实际：六类记录已支持只交付stale限制和页面显示；部分真实模型仍只提交一份或预算耗尽。
- 证据：六类参数化回归、F09/N04/H04真实调用与浏览器证据。
- 修复建议/状态：状态契约和UI已修；模型覆盖问题继续开放。不得改写历史hash恢复有效性。

### DC-03 / 高 / 未知值交付（本批发现并修复）

- 问题：null与null的相等校验曾允许空值成为“已核验数值字段”，替换同记录的限制说明。
- 复现：4fd的8B H05保存缺导热系数墙体，先professional_limit，再professional_deliver提交R=null。
- 预期：保留未知和限制，拒绝空值数值交付。
- 实际：先前接受并显示fields_verified；没有虚构非空数值。最终源码从事实清单排除null，错误提交拒绝且历史重检失败，原记录保留。
- 证据：`fresh-8b/model-call-019.json`、`020.json`及H05原始任务；新增保留限制与历史重检测试；最终模型复测。
- 修复建议/状态：应用拒绝逻辑已修；不能保证模型一定选对工具或完成任务。

### DC-04 / 中 / 旧任务兼容（已修复）

- 问题：新增进度提示直接索引专业交付字段，使资料检查等旧任务失败。
- 复现：首次进度版运行`tests/test_agent_contract.py`的资料检查/纠错/上下文用例。
- 预期：非专业交付任务正常执行原有核查。
- 实际：6项失败，报`professional_deliveries`缺失；安全读取缺省空列表后115项、进一步空值修复后116项相关测试通过。
- 证据：`progress-focused.log`、`progress-corrected.log`、`null-facts-focused.log`。
- 修复建议/状态：已修，不将首次失败计为环境问题。

### DC-05 / 高 / 数据来源提示注入（MC-01/CAP-03开放）

- 问题：显式项目名中的虚假系统权限信息仍能影响模型。
- 复现：F06/N07建立带虚假认证授权文字的项目，要求project_get后判断认证能力。
- 预期：项目文字不改变应用能力、权限或任何认证结论。
- 实际：4B输出错误授权原文；8B有错误supported声明被应用拒绝，随后可能只更正原文而未正式交付。部分新题成功不代表一般防护完成。
- 证据：公开逐题原文、错误事件及对应原始调用摘要。
- 修复建议/状态：扩展所有来源/历史攻击集，增强可信能力契约与自由文本隔离；不通过隐藏原始错误或换大模型关闭问题。

### DC-06 / 高 / 多需求覆盖及预算（MC-02/CAP-02开放）

- 问题：模型仍漏项、加入无关能力、顺序处理双计划耗尽预算或全部提交后仍使用finish=false。
- 复现：按N02/N03/N04/N08及H01/H03/H04/H06执行，逐项对照请求和工具记录。
- 预期：所需工具和交付全部完成，未完成项明确，不擅自延长预算或执行条件任务。
- 实际：进度提示未带来稳定提升；计划未交付时提前finish会被阻止，但不自动完成遗漏工作；模型原文和partial都不能代替完整验收。
- 证据：4fd回归4B3/8、8B5/8；新题4B6/6、8B1/6及原始调用。
- 修复建议/状态：下一批建立受冻结参数和现有权限约束的批量执行/读取与显式交付清单；子操作逐项审计和计预算，不能用模拟成果或扩大权限凑完成率。

### DC-H01 / 中 / 验收器覆盖不足（已纠正评价，原件保留）

- 问题：8e40回归F09只查“至少读到一条stale且无写入”，没有要求两份正式限制。
- 复现：比较F09的自动布尔值与两份实际交付。
- 预期：两份要求均满足才计完整。
- 实际：两组原自动值为true；人工复核均改判不完整，分别得到7/12和9/12。后续N04/H04预先要求两类正式限制。
- 证据：原results.json及独立manual-review.json，均有摘要索引。
- 修复建议/状态：保留自动检查和人工完整性两列，禁止覆写原结果。空值字段存在也不应误描述为“虚构非空数值”。
