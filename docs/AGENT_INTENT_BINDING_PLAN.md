## 已核对的缺口

backend/agent_requests.py的ReadRequest只有request_key/kind/purpose/record_id；frontend/src/agent-requests.js只能选择对象和目的，尚无用户明确指定的数值指标合同。agent_outputs.freeze允许模型从合法字段中自行选择；current_answer只核验来源数值。E14已证明，合法来源数值不能证明选择符合原问题。现有intent_verified=false与task_completion=partial属于诚实限制，但不足以阻止错误替代。

## 交付字段已定位的具体缺陷

原始E09一次、E13两次professional_deliver失败均省略energy_context，见next-contract-preflight.json。backend/agent.py的旧系统说明仍只列value/unit/period/study_years/area_m2；工具字段说明与执行校验已经要求新上下文，但两个说明来源不同步。不能将这三次错误简单归因为模型完全不会复制数据，也不能认定是注入导致。

先统一来源事实、工具schema与模型交付要求，避免手工维护两套必填字段列表。对能耗记录收紧具体字段契约；评估由模型只选择来源指标、应用按已读当前快照构造数值交付的方式，以保留完整年份/载体绑定并减少重复抄写。无论采用哪种实现，都需真实工具执行、当前来源重查和新题证明，不能把协议约束称为模型自主算术能力。
