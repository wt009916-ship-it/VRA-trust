# 证据追溯与工作区可靠性优化

2026-09-26。本轮从 GitHub `main` 的 `06b2f0a` 开始，依据《项目介绍》《技术与验证资料》、商业计划书的产品边界和验收章节，以及随附测试日志，修复已有流程中的失效处理和交互问题。

## 改进内容

|问题|更新后的行为|验证|
|---|---|---|
|一次网络错误就终止运行状态刷新|串行轮询自动退避重试，最多间隔 30 秒；会话过期停止重试。同步失败期间隐藏未重新核验的数值、比较和报告内容|前端模拟断线、恢复、慢请求和退出的回归测试|
|切换项目或选择另一份报告时，旧异步响应可能更新当前页面|导入全过程绑定最初的项目；报告和运行刷新校验请求顺序及当前选择；已经离开的页面不再初始化三维|项目绑定测试、语法检查和构建|
|文件已上传，但来源登记失败后重试会再次上传同一文件|同一导入对话框复用已上传文件，用户修正来源字段后继续登记|模拟首次登记失败及二次成功，核对只上传一次|
|搜索参数关联证据却没有冻结版本|关联证据须已复核；搜索保存其完整快照。撤回复核、修订、损坏和缺少旧版本快照会使搜索失效|证据版本、文件篡改、跨项目绑定回归测试；真实参考流程|
|搜索失效后仍可能在证书字段列出当前反例|当前反例字段置空，补证收益不再发布；历史搜索点保留并标明不可作当前判断|真实参考流程中的证据撤回检查|
|新增前端模块或测试可能未进入本地验证|语法检查自动枚举活动源码，本地验证自动包含全部前端测试|完整语法检查与 18 项前端测试|

反例页面现在可选择关联已复核证据。未关联时仍需填写明确的搜索域依据；该文本不会自动升级为实测证据。已完成搜索会继续检查失效状态，数据未变时保留正在填写的补证表单。

本轮没有修改 `backend/core.py`、EnergyPlus 版本、参考模型、排序目标或碳排口径。假设、未确认资料、预算内未发现翻转和工程师未签署等边界继续保留。

## 本轮验证

- 后端：84 项通过、6 项子测试通过；6 项依赖另一路历史原生运行目录的测试跳过。
- Windows DPAPI 加密测试在本轮修改前即因隔离系统账号无法调用加密接口而失败；总测试明确排除这 1 项，没有修改加密实现或将失败改成通过。
- 前端：18 项通过；全部活动 JavaScript 语法检查、Vite 生产构建通过。
- Ruff 检查通过；OpenAPI 和共享 schema 重新导出后无语义差异。
- `scripts/verify_trust_slice.py`：37 项通过，实际调用 EnergyPlus 6 次。该流程创建独立参考项目，验证三方案、预算搜索、搜索域证据撤回、报告抑制，以及碳重算不调用物理引擎。
- 原始仿真文件逐项哈希保持不变；更新搜索域证据后，原始能耗/EUI 仍有效，搜索结论失效。

以上均为官方参考模型的软件与计算流程验证。运行输出仍保存在本机 `validation/trust-slice/`，不作为真实建筑、材料性能或外部 Provider 验收。

## 依赖与保留事项

构建依赖 `nanoid` 从 3.3.16 更新到 3.3.19，`postcss` 从 8.5.19 更新到 8.5.28，锁文件保留其他包和平台元数据。npm audit 中对应两项告警消除。仅归档前端使用的 ECharts 5 仍有一项 moderate 告警，修复涉及主版本升级，本轮没有替换归档展示栈。活动构建只加载当前工作区与按需加载的 Three.js。

当前自动化浏览器连接不可用，未宣称完成本轮目视交互验收。Three.js 仍有构建体积提示；Starlette/httpx 仍有原有弃用提示。

## 复验入口

```powershell
python scripts/verify.py
python scripts/verify_trust_slice.py
```

真实流程需要安装并配置 EnergyPlus 9.0.1，使用新的隔离运行目录。历史原始运行和证据版本不应通过改写 manifest 来消除失效状态。
