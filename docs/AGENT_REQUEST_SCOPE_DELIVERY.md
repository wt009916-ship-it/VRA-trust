# 显式读取范围与逐项核验交付

2026-11-07。冻结应用提交 `5a1ae508382a27acfc218e6f9e6ff0af11608952`。本批实现用户声明的读取清单、范围约束和逐项状态；没有证明自由文字规划可靠。开发复评仍为 **75/100**，95+未达到。原型和 GitHub 发布状态以本批发布回执为准。

## 已实现的实际调用链

界面“明确读取范围”逐项表单 → `Chat.read_requests` → 本轮不可扩张的专业/目的/编号 → 模型选择真实读取工具 → 来源绑定交付 → 最终重核验 → 当前进度与同源报告。核心见 `backend/agent_requests.py`、`backend/agent.py`、`frontend/src/agent-requests.js`，OpenAPI同步更新。

- 最多6项声明，其中指定结果最多3项；只允许 AI 自由提问的只读任务，与计算计划/允许计算互斥。结构化清单由用户提供，不将模型猜测或历史授权当作本轮范围。
- `availability`只核验当前项目指定编号或该专业完整目录是否存在，不产生工程数值；存在不等于当前结果有效，缺失不证明从未执行计算。
- `results`必须提供对应专业的完整编号，不自动换成最新记录。工具定义及执行时均检查范围；同项目其他编号、历史编号和问题备注不能扩张清单。
- `requested_availability`一次真实SQL快照核查所选范围，保存目录及代码身份；最终及历史访问再核查。目录变化撤销旧回执的当前有效性，原任务记录不改写。
- 声明目标分别显示尚未交付、交付目前未通过核验、可用性已核验、所选结果已核验、当前限制已核验、指定记录不可用。全部声明范围已检查仍不代表自由问题所有要求已完成。
- 保持5轮/15事件和既有恢复上限；不扩大计算权限。读取清单只绑定记录和读取目的，**尚不逐项绑定自由文字中每个事实字段，也不自动消解文字与清单矛盾**。

表单支持加载当前项目真实记录、主动选填编号、手动填写原编号、移除目标和失败重试；不需要输入读取JSON。计算计划的旧JSON输入仍存在，本批不是整体前端改版。
