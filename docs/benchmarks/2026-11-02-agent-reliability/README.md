# 检索恢复、取消与调用预算 · 2026-11-02

## 实现

- 文件名筛选0命中而项目确有文件时，每任务至多一次自动无筛选重查。首次0结果和恢复事件分别保留，恢复origin=recovery；工具返回initial_query_result/unfiltered_retry/scope_changed，不冒充模型自主重试。首批最多5份，保留分页next_offset，不声称已看全量。只读取同项目元数据，不读取文件正文。
- 任务可请求取消，控制记录和执行记录分离，重复请求幂等，写接口仍检查会话/项目/CSRF。在模型请求前后及工具前检查，停止后续步骤，保留已完成产物；运行中/未执行计划步骤标取消。已发出的HTTP、正在运行的原生工具和已提交EnergyPlus作业不强制终止，已发生费用不退回。
- 每任务最多1–8次模型请求，默认8；公开API可选已报告token软阈值，普通UI默认120000且可调。服务端在下一次请求前检查；达到阈值或启用阈值而服务未给用量时暂停。缺失用量不当0。单次返回可能超阈值，Gateway内部网络尝试可能多于模型请求数；这不是CNY费用硬限额，也不是全租户配额。
- 当前请求计数在发出前保存，界面显示用量/次数、停止原因和恢复来源。关联接续新任务可重新声明预算；资料摘录与计算权限仍默认不勾选。达到预算而没有最终说明时标partial/unavailable，实际工具结果保留，不造成功回答。

## 真实DeepSeek官方复验

只读现有正式加密服务配置，所有任务在既有隔离库。输入是四份公开参考文件的目录和合成需求，非客户建筑验收。另用受控响应验收浏览器，不把受控响应混作真实API。

|任务|实际结果|判据|
|---|---|---|
|强制query="原件 上传 文件"、limit=2|初始0命中；服务重查2/4，next_offset=2，4.64秒|两个实际读取事件，origin分别model/recovery；模型正确说明未看剩余2份；自主工具数1|
|列出全部原件|实际返回四份，说明含全部四个文件名，6.91秒|读取结果与保存的模型说明逐名核对，不凭扩展名推内容|

|真实请求期间取消|官方响应返回后cancelled，模型请求1次，已报告5547 token|后续工程工具0；不是中断网络或免除费用|

## 验证与限制

完整回归433项/6子测试通过，随后最后的在途计数/取消与服务错误竞争等6项控制测试通过；59项智能体专项、60项前端、Ruff/契约导出/公开边界/两种构建通过。最后6项控制修订之后没有重复整套完整回归，范围在此分列。隔离浏览器实操任务发起→取消→最终已取消、历史重开与预算，390/1440宽度无横溢出，console error 0；浏览器使用明确标记的8秒受控响应，真实官方取消另见上表。

结构化计划保留已做/失败/跳过/取消状态，但尚无对任意自然语言承诺的可靠通用完成判定。没有持久步骤自动恢复、全局收费预留/结算、跨进程业务幂等、多租户队列和现场校准；进程中断仍标失败，需显式关联接续。材料真实性、复杂全楼、15独立工程/20栋/每功能10真实场景继续未通过。
