# 公开实测计量、1936老图与299空间高楼

本轮结果不是整项目交付验收。**20栋匿名建筑通过真实电表原件进入计量流程；不等于20种建筑几何或15个独立工程通过。** 本轮中央冷站现场校准通过数为0。

## 数据与执行

- [BDG2](https://github.com/buds-lab/building-data-genome-project-2) 固定提交 `9b97ccbe90096aff42ed4fd6493bf7ae692d7118`，Miller等人的[原始数据论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC7591488/)，仓库数据CC BY-SA 4.0。使用原始电表，不用cleaned或filled目录；选取2016年1月，20栋不同建筑ID、19个站点。匿名建筑的形态、安装设备、独立工程归属未知，不能据用途标签推定形态。
- [NIST NZERTF官方数据](https://pages.nist.gov/netzero/data.html)：2013–2014实际测试住宅的室内、室外热泵部件平均功率。研究人员模拟住户使用；不是实际客户中央冷站。两个通道属于同一栋建筑，不能算两个项目。
- Fraunhofer Twin Houses Annex71冬季试验原包和说明书已取得，**尚未完成模型对齐与实测误差验证**。[官方来源](https://fordatis.fraunhofer.de/handle/fordatis/161.2?locale=en)。Google SB1仅检查公开压缩包目录，未执行其设备数据校准。
- 来源地址、文件大小和SHA256见[sources.json](sources.json)；原包留在仓库外，不重新分发。
- 批量请求使用FastAPI TestClient、真实业务服务/文件存储/隔离SQLite，不冒充外网或并发HTTP测试。另用真实Chromium访问独立loopback服务完成NIST上传与页面操作。

## 计量实测结果

完整逐栋结果及每次失败见[meter-results.json](meter-results.json)。20栋各执行项目建立、CSV上传、分析入库、历史读取；每栋744个小时。**12栋时序/数值检查通过、8栋有缺测**。Swan_unknown_Allison整月744条均无读数，保留为失败，不补零或换掉样本。

12次误差比较中10次成功、2次因实测均值为零返回409。预测器为透明的小时均值基线：前14天训练24个小时均值，后17天完全留出；不是大语言模型、不是EnergyPlus物理模型，更不是客户现场校准。成功案例留出CVRMSE约0.73%–76.76%，均逐项公开；不挑低误差证明商业准确率。训练/留出样本336/408，训练自由度312、留出408，NMBE符号为预测减观测。

NIST两通道原始文件各8761行，8632条有效、129条缺测。按原始带偏移时间解析，W间隔平均功率转换为kWh；不把缺测后的有效行总和称全年总量。两通道均阻止误差比较。全部结果`calibrated:false`。

用户界面：项目 → **计量与验证**，无需先建立几何模型。CSV原件、单位、计量边界、时区、预测/观测性质和依据分别保存。缺测、重复、非数值、负用量、时间缺口和错误口径不自动修正。累计表底和瞬时功率不属于当前输入契约。历史分析绑定原件/解析规则，规则变化后比较须重新分析。

浏览器实际执行：NIST原件上传、读取列名、空必填阻止提交、完整填写后201、显示129条缺测；1440/1024/390屏宽页面无横向溢出。该检查不替代跨浏览器密码库或生产容量验收。

## 老图修复

与[前轮失败](../2026-10-28-drawing-systems/README.md)使用同一1936 HABS马车房再版图、第24页、相同比例/裁切/两条人工门槛分区假设。旧实现遇内部线岛就丢弃整个房间；现在把观测像素单元合并为合法多边形，保留内部岛，按面积变化预算约束简化。

候选从5到11，恢复约102.03m²大空间。原图叠图已目视复核，但**不是11个真实房间全部判对**。比例15ft/117px仍为人工近似，人工门槛闭合不是源墙证据；标注线、楼梯和真实孔洞仍需工程师判读。内部岛未记录复核依据时不允许确认模型。没有独立真值分区或整层准确率。[候选面积、来源、参数](historic-drawing.json)。

## 高楼修复与仍失败的部分

真实De Zalmhaven结构IFC恢复的同一299候选空间，保留前轮三维细分几何逐空间重放。修复任意5cm宽度阈值排除可表达外墙，以及原生内缩对狭长凸面失效时的等比缩放开窗。只适用于明确WWR假设，不改变源窗，也不降低总开窗面积。

逐空间分配失败从218降至39，原R2通过。**其余39仍失败，全年EnergyPlus运行0**。[所有剩余失败](glazing-summary.json)。微小碎面仍无法承载合法窗面；后续引擎小面/短边预检仍保留，分配通过不能直接叫仿真通过。

另做了保留凸多边形的私有热网格实验：引擎预检问题5515降至2325，但引入非流形/退化问题，未合入产品。不能通过删空间、删窗或把失败计为成功来绕过。

## 复跑与证据

在安装项目依赖和Node的环境中，把指定原始文件放到仓库外的`source-dir`：`bdg2/metadata-original.csv`、`bdg2/electricity.csv`、`nist/HVAC-hour.csv`。来源URL见sources.json；脚本硬校验3份原件哈希，不接受改写或填补版。

```powershell
.venv/Scripts/python.exe scripts/verify_public_meter_data.py --source-dir D:/public-meter-sources --output-dir D:/meter-acceptance-new
```

输出目录必须不存在；只在新目录创建隔离数据库和测试账号。生成的`access.private.json`用于隔离浏览器验收，不提交、不用于正式环境。`execution.json`记录代码/原件哈希，`completed.json`确认执行期间代码未改变，`results.json`逐项保存失败。固定一月子集限制也是结果的一部分，不代表全年完整QA。

首轮完整回归331通过/2跳过/2失败，失败是未设置ENERGYPLUS_EXE；补配置重跑核心31项及6子测试通过。损坏CSV额外防护后完整回归与本机更新结果见[checks.json](checks.json)。保留前轮失败，没有回写旧manifest。
