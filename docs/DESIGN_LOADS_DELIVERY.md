# 设计日、分区显热负荷与可核验 Agent 结果交付

本批在真实 EnergyPlus 9.0.1 链路中增加分区设计显热负荷、设计工况与来源绑定，并在 Agent 中交付服务端当前核验结果。限定范围是模型设计情景，不是当地设计气象认证、全楼同时峰值、潜热总冷量、设备选型或实楼验收。最终应用源码为 `03bda16d411705affa56396768ed5b3b573cbfbe`；后续报告和证据提交不应修改该应用代码。

## 已实现的调用链

`core.run_simulation → 原生 SQL ZoneSizes / IDF SizingPeriod:DesignDay → design_loads → result/manifest → 当前 domain.view → API / PDF / ZIP / 前端 / Agent simulation_artifact`。逐行保留冷热类型、W、风量、分区/分组倍率、用户裕量、设计日对象位置、峰值日期时刻、室外条件及来源摘要。原生结果已应用的倍率不再相乘。可用时与 HVACSizingSummary 对照；缺失、无效、异常单位或模型绑定不一致均不伪造数值。

运行列表给模型摘要，逐项结果按 5 行分页。run_id、当前 receipt_hash、整数 offset 必须共同校验，控制器读取不冒充模型读取。模型只有真正读完当前目标的所有行，显式 finish 才被接受；正式数值卡再次从当前服务端读取。模型提前结束的错误文字保留在审计中，不作为工程结果展示。失效后的历史查询移除旧数值，不改写旧任务事件或原生 manifest。

## 浏览器与发布一致性

第一轮浏览器用初版设计负荷应用新跑一次全年参考，核对全部 10 行 W/kW；7 页 PDF、ZIP 中 28 个 manifest 附件及 JSON 数值一致，撤回复核后结果失效，原件摘要不变。第二轮用 `af8dcf6` 新建隔离账号、项目及真实运行，在本地工具模式核验 Agent 原生卡、历史重新失效和审计事件不变。390px 视口没有整页横向溢出；长表在内部滚动。两轮均无页面异常，测试服务已停止。

第二轮浏览器与最终应用仅差显式模型分页 finish 协议及其测试，所有前端字节相同；最终真实模型/API 验收使用 `03bda16`。不将浏览器冒称在最终后端提交执行。Git 精确源码检查覆盖 236 个选定文件，8 个仅 CRLF→LF 差异单列并验证 JSON 语义；从最终 Git 字节构建的 5 个资源与浏览器验收资源逐字节相同。详 `browser-source-delta-v1.json`、`git-source-v3.json`、`git-assets-v5.json`。

桌面固定输入区遮挡部分结果表，小字、长表与历史 JSON 对阅读仍不友好；本批不是整体视觉重构，用户体验分不增加。本机原型更新必须先通过发布核验，保持 174 条 records、3 条 jobs 及参考指针摘要；旧物理运行因版本变化保守失效，不自动重算、不重写历史。
