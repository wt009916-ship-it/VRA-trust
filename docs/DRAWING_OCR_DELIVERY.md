# 图纸文字识别与可追溯复核验收

2026-11-05，工作包4的OCR子批。新增真实本地PNG/JPEG及PDF逐页光栅OCR、位置叠框、模型分数、人工更正及不可覆盖历史。本批没有训练模型，也没有完成墙线修复、缺失尺寸补全、构件识别、跨图关联或专业审图。开发复评69/100，不能据此宣称95+。

## 实际调用链

认证上传并保存SHA-256 → drawings.py检查项目/格式/容量 → 独立drawing_worker.py子进程 → Pillow方向规范化/白底合成，或PDFium 150 dpi光栅化 → RapidOCR 3.10.0 + ONNX Runtime CPU → 原文/四点框/分数/模型身份 → SQLite版本记录及独立PNG预览 → 浏览器逐条复核/JSON导出。没有占位OCR或在线模型回退。

三份随固定依赖安装的ONNX权重均检查SHA-256，缺失/被改动拒绝运行，不在推理时自动下载。来源为RapidOCR打包的PaddleOCR模型；权属和完整许可见third-party/rapidocr-3.10.0/，不声称为自研权重。检测最长边1600、全图处理最长边4000、CPU线程2、保留低分候选，设置写入结果。模型识别分数不是正确概率或工程可信度；高分也须复核。

候选固定为AI_INFERRED。复核限定已有候选，允许确认、更正、拒绝、无法辨认，默认无法辨认；人工更正单独存储为HUMAN_TRANSCRIPTION，不改模型原文或原图。服务端记录账号、时间、依据，revision比较防止覆盖并发修改。复核不能自动改变项目工程参数、资料确认或仿真准入；测试明确断言工程项目与evidence无新增。此处“人工”描述产品复核通道，本批由自动化验收账号操作，不冒充外部工程师认可。

parser_hash绑定工作器源码、模型契约/实际权重哈希及关键包版本。来源/预览损坏、模型或依赖变化后旧结果stale，隐藏候选和当前复核，保留原件与历史。列表仅返回摘要，按记录加载明细。

## 边界与资源

文件1字节至10 MiB；仅单帧PNG/JPEG，Image.open只允许对应两个解码插件；PDF最多200页，每次显式选1页。最大1200万像素及6000边长；PDF分配前按PDFium每轴ceil检查实际光栅预算。EXIF方向应用后坐标关联规范化预览，不直接当作工程单位。PNG透明背景合成为白色，原件不变。PDF不走原文提取捷径，也不生成不存在的尺寸。

单进程单OCR槽、每任务60秒、每项目50条OCR记录、最多500候选，每条2000字符，输出JSON 2 MiB/预览40 MiB上限。环境白名单不转发Provider密钥；禁用ONNX遥测、拒绝工作器内Python socket连接。**这些不是OS级网络/内存沙箱**：原生库内存分配、长期并发/磁盘配额、无限复核历史尚未完整验收，仍保留高优先级缺口。失败保留原件且不伪造识别成功。
