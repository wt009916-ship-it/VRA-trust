# 核心功能升级：资料诊断、材料验证与工程决策

2026-09-26。本轮按项目介绍、技术与验证资料、商业计划书及测试证据中的业务流程，新增可运行的材料决策闭环。资料中的愿景与性能陈述不作为已验证结论。开发分支为 `feature/core-decision-upgrade`，通过 PR 交付。

## 新能力

| 环节 | 可执行功能 | 输出依据 |
| --- | --- | --- |
| 资料诊断与补证 | 综合输入准入、图纸/账单、建筑声明、材料记录和最新研究生成分级待办，点击跳转处理 | 当前项目的证据、版本、准入与运行状态 |
| 材料验证 | 登记、修订材料卡，关联热工、批次、对照和老化证据；检查参数、来源、测试条件、适用范围及人工复核 | 材料版本和来源快照；假设与导入资料保留原性质 |
| 真实方案比较 | 从有效 baseline 列出实际关联表面的材料层，按所填材料参数和厚度生成候选 IDF；逐个调用 EnergyPlus | 新运行的原生 SQL、ERR、manifest、输入和哈希 |
| 工程筛选 | 选择能耗、增量初始造价、占用制冷未达设定点小时数、运行 CO₂ 目标；设置造价、供暖/制冷舒适性和节能率约束 | 可行、超限、缺数、失败状态和非支配候选；逐项排除原因 |
| 助手执行与解释 | 读取真实诊断、执行用户提交的结构化研究计划、解释最新有效候选及下一步补证 | 工具时间线、研究 ID 和结果报告；禁止自行编造计算计划 |
| 工程报告 | 导出 JSON、HTML、PDF 和原始证据 ZIP | 同一个评估快照，包括目标、范围、材料/费用来源、取舍和待办 |

## 使用步骤

1. 创建项目，在“资料”导入并复核 IDF、EPW 及相关资料；在仿真页完成有效 `baseline`。官方参考入口可用于熟悉流程。
2. 打开新增的 **材料与决策**。先查看诊断待办；导入材料检测/文献和造价依据时，填写定位及来源并人工复核。
3. 点击“登记材料”，填写导热系数、密度、比热、测试条件和适用范围，关联来源。缺少资料可保存待补齐卡；确认参数前不能进入仿真。
4. 选择基准运行、要替换的实际材料层，核对列出的构造、表面和区域。添加候选材料、厚度、造价、造价来源和计价范围。
5. 选择目标，填写工程约束、研究依据和最多运行候选数。点击“开始真实方案比较”或“由助手执行这份计划”。
6. 查看完整指标、约束违反和方案支配关系，再下载报告与原始证据。非支配候选可能有多个，包含“维持现状”；它们需要按实际工程条件复核。
7. 材料/证据变更后研究失效，应新建研究。仅碳因子变更时点击“仅重新评估”，复用物理结果重新筛选，无需再调用引擎。

## 模型与证据边界

- 一次研究替换一个普通不透明 `Material` 对象的厚度、导热系数、密度和比热；该对象关联的全部表面同时受影响。不是自动给外墙增加一层，也不自动识别只应改造的表面。特殊 `MaterialProperty:*` 或无表面映射对象不支持。
- 保留粗糙度、光学吸收率、其他构造、HVAC 和时段。材料参数遵循 [EnergyPlus 9.0 Material 对象定义](https://bigladdersoftware.com/epx/docs/9-0/input-output-reference/group-surface-construction-elements.html#material)。当前参数域不能模拟稀土涂层的全部光学机理。
- 至多提交 12 个候选，预算内按提交顺序计算；报告显示未测试候选和实际调用次数。离散候选集内的非支配关系不等于连续空间的全局最优。
- 造价为用户有来源的增量初始造价，未知保持空值；维持现状的改造增量为 0。尚不计算电价、运行费用、净现值或生命周期收益。
- 舒适性采用原生 SQL 的 Facility 占用时段未达设定点小时数；供暖、制冷分别处理，不相加为总时长。是否满足工程标准由用户声明阈值及专业复核决定。
- 来源复核不会把 ASSUMED 或 IMPORTED 转成实测。材料卡和参考仿真不能证明材料性能优势；报告为未签署工程草稿。
- 输入、材料版本、证据、代码或原始输出失效时隐藏当前评估，不改写历史来消除失效。新研究失败时助手不会回退引用旧候选集。
- 本轮诊断使用已有结构化数据与证据；任意残图 OCR、自动材料测试结果提取、HVAC 连续优化、真实建筑校准和外部 Provider 联网验收仍待后续实现/验证。

## 验证记录

- 最终后端完整回归通过 105 项及 6 项子测试，其中材料决策专项 21 项，包括参数限制、权限、跨项目隔离、失效、缺数、约束、候选集和报告。PDF 排版最后调整后，导出专项再次通过。
- 前端 22 项测试通过，语法检查和 Vite 生产构建通过；后端 Ruff 和契约导出通过。
- 最终真实流程 `scripts/verify_material_decision.py` 通过 30 项检查：1 次基准 + 2 次候选实际 EnergyPlus 调用，另 1 个候选明确未测试；助手提交、因子变更零引擎重评估、报告/ZIP、证据撤回和历史保留均验证。
- 该验收显式使用官方 US-CO 927.2 m² 参考模型、假设材料与假设造价。材料层 IN46 替换为 0.08/0.12 m 的测试值，年能耗分别为 57,060.34 / 56,118.70 kWh；基准为 57,193.23 kWh。能耗下降伴随费用和制冷未达时长上升，因此保留多方案取舍，不能用于宣传实际节能成绩。
- 最终真实流程记录在本地 `validation/material-decision/latest.json`；运行、数据库及用户原始资料不进入 Git。
- 最终 PDF 四页均已渲染检查。浏览器控制连接不可用，本轮未完成新界面的浏览器目视验收。
- 6 项已有原生历史运行测试因缺少目录跳过；Windows DPAPI 用例受当前隔离账号限制单独排除并保留问题记录，未更改密钥保护逻辑。GitHub Linux CI 结果以对应 PR 为准。

## 代码入口

- `backend/materials.py`：材料卡和版本化证据关联。
- `backend/decision.py`：诊断、IDF 映射、真实仿真、约束与非支配分析、失效和因子重评估。
- `backend/decision_api.py` / `decision_reports.py`：项目隔离 API 和报告。
- `backend/agent.py`：诊断和受控研究工具。
- `frontend/src/decision-ui.js`：“材料与决策”工作界面。
- `shared/schemas`：材料、研究计划和 OpenAPI 契约。

原有 `backend/core.py`、参考输入和历史结果保持原样。
