# 原件存储配额

服务启动时读取下列正整数配置，MB均表示MiB（1024²字节）。0、负数、小数或无穷值不表示关闭限制，会使启动失败。单文件上限256MiB，文件数量配置最大20000。

|环境变量|默认|含义|
|---|---:|---|
|VRA_MAX_UPLOAD_MB|20|单文件上限，API和内部参考导入共用|
|VRA_SOURCE_PROJECT_MB|256|单项目已登记原件累计大小|
|VRA_SOURCE_TOTAL_MB|1024|本机原件目录总大小，含未登记遗留文件|
|VRA_SOURCE_PROJECT_FILES|1000|单项目原件份数|
|VRA_SOURCE_TOTAL_FILES|10000|本机原件目录文件数，含未登记遗留文件|
|VRA_STORAGE_RESERVE_MB|256|新增原件后至少预留的磁盘空间；仅预检|

修改后重启本机服务。旧原件超出新限额不会删除或改写，下载和历史仍可访问，新增原件被拒绝。管理员应根据实际容量调整配置；本产品没有通过删除历史来回收份额的自动功能。备份包仍有独立4GiB/20000文件上限，调高原件上限不会同步调高备份格式上限。

`GET /api/projects/{project_id}/storage`须会话和项目归属，返回本项目用量、单文件/本项目限额、共享容量是否还有余量；不返回其他项目清单或全局用量。导入窗口显示实际配置与最新用量，最终以提交时事务检查为准。507错误含稳定`code`，单文件超限413，原件清点异常409；不会把失败写成成功。

已有原件的大小/身份与登记不一致时暂停新增，原下载仍由原有SHA检查决定。清点不是对全部原件做逐字节hash审计。扫描上限50000项；目录包含链接、子目录或非普通文件时拒绝新增，不递归跟随。若进程被杀导致孤立文件，它仍占本机配额；先备份和人工核对，不应随意删除疑似原件。

来源登记与一般用户上传是两个API请求。当前弹窗在来源校验失败后可复用已上传原件；刷新页面、关闭弹窗或丢失上传响应不保证幂等去重。参考项目则使用同一批事务注册项目/原件/证据/归属。

复现：`python -m pytest tests/test_storage.py -q`；`python scripts/verify_storage_quotas.py validation/new-quota-run`（输出目录必须不存在）。后者仅使用合成数据与新隔离数据库，执行24并发ASGI上传、实际磁盘和SQLite计数、加密恢复，不访问正式runtime，不发外部模型请求。不能据此声称整个服务有操作系统磁盘配额或完成生产压测。
