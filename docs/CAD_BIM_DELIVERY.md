# CAD/BIM只读解析阶段 · 2026-11-04

新增DXF/IFC实际解析；不是完整CAD编辑器、DWG转换器或自动图纸识别。解析库固定ezdxf 1.4.5、IfcOpenShell 0.9.0.post1。依赖参考：[ezdxf外部参照说明](https://ezdxf.readthedocs.io/en/stable/xref.html)、[IfcOpenShell代码示例](https://docs.ifcopenshell.org/ifcopenshell-python/code_examples.html)。

## 实现与限制

项目上传→哈希核验→独立子进程解析→保留不可覆盖的解析记录→界面清单与JSON导出；原文件可下载。解析器源码或库版本变化、原文件损坏使旧记录失效。身份、项目归属与CSRF沿用业务中间件。

DXF：模型空间顶层实体类型、图层、标识、LINE坐标/长度、文本和块名。单位明确时换算米；单位为0保持null。块不展开、外部参照不读取、图纸空间不计入；图层名不冒充建筑构件语义。DXF审计发现需要修复则拒绝，不静默恢复。

IFC：IfcProduct类别统计、GUID、名称、单值实例属性、显式单位、声明的空间归属、缺少位置的完整性提示。缺单位不猜测；重复GUID、非单项目文件拒绝。尚不含几何网格、类型继承、复杂属性、QTO、碰撞或空间邻接。

每文件最大10 MiB、最多10000个顶层实体/产品、结果最大8 MiB、30秒子进程超时、同时最多2个解析进程。子进程隔离不是操作系统安全沙箱或硬内存限额；复杂恶意文件的资源耗尽仍须单独验收，不能宣称安全满分。

子进程只继承必要系统环境，不继承Provider密钥；工作目录和配置目录指向临时目录。精简环境的首轮3项DXF测试因库需要用户目录而失败，补充临时USERPROFILE后8项全部通过（sanitized2.log）；失败日志sanitized.log保留。

## 问题跟踪

CAD01 / 文件能力 / 高：原IFC只允许上传，DXF无法上传。复现：上传后缺少构件读取接口。预期：真实解析及明确范围。当前新增上述限定读取与测试；复杂模型、DWG/OCR仍待开发，不能标记整个原审计D08–D12关闭。

CAD02 / 稳定性 / 中：本批原生解析器虽有进程超时/大小/数量限额，但没有硬内存隔离。复现：仅在受控资源环境构造复杂大文件，尚未执行资源耗尽实验。预期：资源预算内可取消、可恢复；当前部分实现，证据为cad.py限制与超时测试。建议后续使用OS级资源限额和任务队列，保持待验收。


## DWG转换候选（2026-11-08，基于未发布PR60）

新增真实流程：上传保留DWG → LPAC隔离ACadSharp转换 → 独立隔离严格DXF解析 → 展示转换通知和限定几何 → 当前来源复核后下载DXF。原件不改写、不自动修复、不声称无损；有警告的结果明确为部分信息。来源、转换副本或引擎变更时撤下数值和下载。冷备份/恢复保全5个上传原件及3个转换副本，新增恢复回执是预期行为。

LibreDWG预筛9例“可读取”不足以支持应用通过：补查严格audit后，9例及新增3完整图均需修复，停止接入而未降低门槛。替换ACadSharp后同12例11例严格通过；原冻结AutoCAD属性转储的9例坐标、长度、面积、文字按半个末位小数容差全部匹配。旧R14完整图仍拒绝。通过样本仍有不支持对象/样式的通知，不能从几何匹配推断全图信息完整。

应用使用真正回环HTTP、新数据库、新账号、原生转换器和原生解析器：3个成功样本、R14及损坏文件2个拒绝；双阶段隔离回执、字节保持、下载、来源/派生/运行时篡改撤证、CSRF、匿名及跨用户保护有证据。相关后端初次92通过/1失败/1跳过，失败为测试连接Row类型与备份函数普通连接不符；修正后的备份及跨用户针对性2项通过，累计93个不同检查通过、1跳过。前端相关20项通过，构建通过（既有Three大包警告保留）。完整CI另以最终提交回执为准。
