## 已实现的用户任务

用户在规范资料页选择“自然语言语义候选”，输入需求和历史/已核验日期，应用仅从本项目当前已复核、未失效且日期符合声明的摘录中检索。提供候选条款、原文、原PDF页和复核来源；相似度不显示为置信度。候选状态明确“相关性待核对”，不自动把首条当答案。保留关键词/精确查找作为独立选择；缺模型或推理失败不会伪装成语义成功。

明确规范编号或条号优先按原精确规则处理，不用向量近似替换不存在的条款；多精确目标仍按旧批量接口，不能混入语义模式。模型仅执行检索，不生成规范原文。模型/分词器版本或来源变化后，保存查询和Agent中的对应来源卡失效；旧记录保留。推理结束和事务保存前重查目录，防止推理期间撤证仍交付旧条文。模型变化只撤回语义结果，不影响有效关键词结果。

32条摘录跨两份住建部公开2021版规范，页面由实际隔离OCR读取，再由开发侧对照原页核对文字；不是外部专家真值。表格没有转录，相关条款明确excerpt。测试日期使用2022-04-01，不声明2026现行性；2026查询实际被有效性复核门禁排除。OCR候选采用整页关联以保留原页出处，不宣称精准自动条款分割。

## 模型与资源边界

固定Xenova/bge-small-zh-v1.5转换版本75c43b069aac4d136ba6bc1122f995fedcfd2781，基于BAAI的MIT模型；FP32 ONNX、归一化CLS、余弦排序、官方中文查询前缀。模型和分词器SHA256见semantic_models.py，推理不下载、不开远程代码。CPU双线程、一次一个检索工作进程；复用只读公开运行时快照，输入私有隔离复制，Windows LPAC无网络capability。实际receipt确认文件/网络边界及Job预算。

最多2000条、50万字符、2000个512-token重叠分段、2MiB请求；查询超过512-token拒绝提示缩小，不截断。内存2GiB private committed、用户CPU60秒、墙钟75秒；Windows映射内存不受该指标完整约束，输出总量为50ms轮询限制，不宣称OS硬磁盘配额。Linux路径有实现，真实Linux模型推理尚未验收；CI脚本协议通过不能替代它。

公开参考32条温启动实际API约6–8秒、首个约11秒，明显慢于约0.4–0.5秒关键词查询；尚无大型语料/多用户吞吐保证。每次查询验证模型和依赖，撤回时宁可拒绝。运行时无业务向量持久化或跨项目共享输入。

## 安装与使用

1. 在应用环境安装主依赖，再执行`pip install -r backend/requirements-semantic.txt`。
2. 显式执行`python scripts/prepare_semantic_model.py --output <独立模型目录>`，验证固定摘要；已有不匹配文件不覆盖。
3. 设置`VRA_SEMANTIC_MODEL_DIR`为该目录并重启自己的候选服务。默认未配置时不启用模型，也不自动下载。
4. 通过规范资料页选择语义候选，或POST现有standard-queries接口，加入`retrieval: "semantic"`。原接口默认lexical。

模型权重不进入Git/项目备份；自建服务安装和本机正式原型切换不在本批执行。公开原PDF、全文转录和原始API产物留在本机参考目录；仓库保存来源定位、文本摘要、排名、边界回执和原文件哈希，不复制完整条文。外部复现需按公开原页重建相同摘录；本机完整冻结文本可直接复核。
