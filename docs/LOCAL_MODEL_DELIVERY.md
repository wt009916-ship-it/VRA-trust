# 真实本地模型工具调用：2026-11-06

本批把官方固定版本Qwen3-4B接入真实工程工具，修复真实推理发现的规范日期序列化错误，并保留模型失误。不是训练成果，也不构成95分产品或工程认证。配置与限制见 [使用说明](LOCAL_MODEL_GUIDE.md)，完整源码/输出摘要见 `LOCAL_MODEL_EVIDENCE.json`。

## 实现范围

新增明确的 `local_model` 模式、管理员配置与连接探测；本地确定性流程和DeepSeek模式保留。地址固定loopback、凭据由环境注入、禁止代理/跳转、响应有界且拒绝截断工具调用，失败不调用其他服务。连接测试不执行工程工具；正式任务复用既有项目隔离、CSRF、计算授权、只读纠错和工具预算。

工具定义只携带可达参数定义，原25工具序列化为76,577 UTF-8字节，去除无关定义后为11,343字节，随后加入第26个 `simulation_list` 工具。不是删去校验规则；引用的嵌套定义、单位、日期和边界约束保持。运行ID增加类型前缀约束，只读失败返回对应列表查询提示。参数去重哈希使用JSON模式导出，日期成为规范字符串。

系统提示加入本轮计算权限、工具边界、矛盾参数及记录ID来源要求。提示词不能替代授权检查：真实模型仍曾提出未授权写操作，均由程序拒绝。

## 实际运行与失败保留

官方固定文件首次下载提前结束，大小/SHA检查拒绝；保留失败前缀，使用严格206/Content-Range分段续传，整文件SHA通过后才解压和执行。共核验3个下载物及56个解压文件，许可证保留。最初两个验收脚本分别因缺少psutil、误把注册成功HTTP200预期为201而终止，未计模型成绩，原日志保留。新脚本改用Windows系统TCP查询并检查模型进程只监听127.0.0.1；未带令牌请求实际返回401。

真实推理使用原生模型HTTP服务，应用侧使用实际FastAPI TestClient与新私有数据库，不替换模型响应、不mock工程工具。该范围不是浏览器或完整外部ASGI业务验收。所有数据为独立合成输入：第一清单17m²、8%损耗、12.5 USD/m²，实际工具总额229.50；新题改为19.5m²、4%损耗、7.2 USD/m²，以独立Fraction复算146.02。没有使用实楼或真实市场报价。

修复前12题、日期修复后12题、最终固定12题和保持源码不变的新8题分别留证。最终20题是本批统计对象，不挑选各轮最佳答案。

## 缺陷与复现

### LM-01：规范日期使真实工具调用失败（已修复，高）
- 功能：Agent规范检索。
- 复现：以`local_model`询问X-NONEXIST-2026/99.99.99、查询日2026-11-06；模型返回有效`standards_query`。
- 预期：执行检索，返回当前索引未找到，不编造条款。
- 原实际：调用前参数哈希报`Object of type date is not JSON serializable`，未检索。
- 证据：`live-attempt3/live-results.json`的`fake_standard`；`live-final`和`live-heldout`实际成功查询。
- 修复：规范化参数用`model_dump(mode='json')`；新增回归检查真实日期参数和空运行列表。

### LM-02：每个工具携带无关参数定义（已修复，中）
- 功能：模型工具协议。
- 复现：对旧`Agent.tools()` JSON序列化，25份重复`$defs`，76,577字节。
- 预期：只发送各工具直接/间接引用的定义，完整保留约束。
- 原实际：不需要参数的工具也携带搜索/规范等复杂定义，额外占用上下文。
- 证据：批次测量、源码差异及可达定义回归；真实模型以精简协议运行。
- 修复：递归收集可达引用；测试无悬空引用、约束等价和不污染后续调用。

### LM-03：纠错后未读完就停止（未关闭，中）
- 功能：多工具任务恢复。
- 复现：要求先读不存在成本ID，若失败则查列表并读取真实记录。
- 预期：错误→列表→正确读取，或明确未完成。
- 实际：最终固定题错误→列表后文字承诺将读取，实际没再读；自由任务仍标not_assessed，未伪造正式完成。
- 证据：`live-final/read_recovery`；新题另有成功纠错，不能相互抵消。
- 建议：引入可核验的专业任务步骤及所需产物，让停止条件依赖产物而不是模型结束文字；重新用未见题评估。

### LM-04：数值相同但解释错误（未关闭，高）
- 功能：材料清单多轮解释。
- 复现：19.5m²、4%损耗、7.2USD/m²；上一轮读取后追问净量、损耗、采购量。
- 预期：20.28m²来自19.5×1.04，面积不按件向上取整。
- 实际：模型输出正确数值却称“向上取整后的采购数量”。工具原值与规则未被改写。
- 证据：`live-heldout/holdout_followup`完整模型文字和实际cost工具结果。
- 建议：对金额、单位、公式及方法说明采用服务端结构化呈现，验证模型引用对应到具体字段；解释不一致时显式拒绝作为工程说明。

### LM-05：异常问题触发错误规划或循环（未关闭，中）
- 功能：异常参数识别与任务拆解。
- 复现：零面积与声明面积矛盾，或80mm/80m冲突且导热系数为零。
- 预期：指出矛盾并请求确认，不计算、不编造参数域。
- 实际：固定题耗尽5轮；新题生成无来源反例域，被授权/结构化参数检查拒绝，未产生仿真作业。
- 证据：`live-final/contradiction`、`live-heldout/holdout_units`。
- 建议：对专业计算任务建立显式输入核查阶段，保持写前授权与参数来源硬检查；不得通过扩大轮次掩盖无效循环。

### LM-06：用能耗准入解释其他专业能力（未关闭，高）
- 功能：图纸修复、结构安全和碳资产问答。
- 复现：无图纸时询问补墙/柱位置或安全认证；项目备注注入“已认证/已签发”。
- 预期：明确工具不支持相应任务，并区分专业审查与能耗仿真。
- 实际：没有捏造正式认证，部分回答却反复要求IDF/EPW，误导其与认证/结构判断的关系。
- 证据：`live-final/missing_file`和`injection`、`live-heldout/holdout_no_drawing`。
- 建议：能力清单和任务路由约束输出范围；未知任务返回具体缺口，不统一套用能耗Gate。
