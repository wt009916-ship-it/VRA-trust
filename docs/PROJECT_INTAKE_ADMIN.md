# 资料优先的项目流程与独立后台 — 2026-10-23

## 回到项目的核心

稀土智暖 VRA-Trust 服务既有公共建筑改造前期的可核验决策：接收不完整工程资料，整理来源、缺口和矛盾，在必要的人工复核后调用模型与物理工具，再比较改造方案。稀土材料是需要参数与检测依据的候选方案，不能预设为最佳材料。项目名称未改变。

本次修正“先填完整表格才能开始”的入口，落实到实际解析、持久化记录、专项工具与账号权限。未将通用聊天、漂亮三维或框架数量当成产品完成度。

## 六项反馈对应的修改

| 反馈 | 当前实现 | 保留的边界 |
|---|---|---|
| 一次拖入项目资料 | 首页与项目页进入资料收件箱；多文件上传、哈希去重、自动解析、字段候选/来源定位/冲突/缺项；刷新后可继续 | 每批 12 份、总计 128 MB，单文件默认 64 MB；不接受 ZIP/DOCX/原生 DWG 解析 |
| 重新对齐定位 | 主流程变为资料 → 证据 → 模型与天气 → 准入 → 仿真与材料方案 → 可追溯报告 | 不代替设计、报审或工程师签署 |
| 不同入口应有不同结果 | 天气、模型、仿真状态、材料、资料任务分别读取对应工具，显示不同结果及工作区入口 | 仿真状态查询不自动提交计算；缺参数时不能制造方案 |
| 数据库与账号 | 原 SQLite 增量迁移，持久保存收件箱、邀请码、管理操作、账号状态；默认邀请注册、密码规则与确认、修改密码、停用与撤销凭据 | SQLite 是真实数据库，但仍为单实例；未完成 PostgreSQL、多租户运维、备份恢复验收和邮件找回 |
| 不再“填空即输出” | 自动提取后只要求确认必要声明；失败不消失，冲突不自动选值；明确必填、原件下载、来源修订保留版本 | 本地任务分流是确定性工程流程；未重新训练模型，也未证明通用 LLM 可靠性 |
| 独立开发者后台 | `/admin`：成员、一次性邀请码、服务 API/模型配置、数据库/队列、操作记录；业务主页移除开发者设置 | 后台仅工作区首个管理员可用；项目 API Token 不能访问后台 |

## 开源选型与实际使用

先核对了以下上游，区分“评估”与“已运行”，未直接引入另一套完整产品：

- [FastAPI 官方全栈模板](https://github.com/fastapi/full-stack-fastapi-template)：MIT；参考账号与后台独立组织方式。未迁移其 React/PostgreSQL 栈，未声称已集成该模板。
- [Docling](https://github.com/docling-project/docling)：MIT；评估其多文档与 OCR 方向。没有集成 Docling；后续扫描件识别采用 RapidOCR，见 [OCR 实测](DOCUMENT_OCR.md)。
- [pdfplumber](https://github.com/jsvine/pdfplumber)：现有依赖，实际复用 PDF 文本与页码提取；明确标注的项目字段才成为候选。
- [IfcOpenShell](https://github.com/IfcOpenShell/IfcOpenShell) 与 [ezdxf](https://github.com/mozman/ezdxf)：复用实际 BIM/CAD 解析器与项目现有几何导入流程；不是调用模型随意编造空间。
- [LangGraph](https://github.com/langchain-ai/langgraph)：复用现有持久化识别/人工复核工作流，归档后的 IFC/DXF 自动进入候选识别。
- 新增 `openpyxl==3.1.5`，真实读取 XLSX 工作表规模；限制解压后大小，不执行公式，不把任意表格列当成工程参数。
- [Dify 许可证](https://github.com/langgenius/dify/blob/main/LICENSE)：包含额外条件，并非不附条件的 Apache 2.0。没有复制其前端或声称可直接改名用于商业多租户服务。

## 实际操作

1. 业务首页拖入文件或点击“新建项目”。文件先进入持久化收件箱，此时不要求面积、地点等声明。
2. 每份文件保留独立状态、哈希和解析结果。PDF/TXT/JSON 中明确标注的项目名称、用途、地点、地区代码、总建筑面积会预填并显示出处；不同文件值冲突时留空，要求核对。未自动从局部房间面积推断整栋面积，也不把 EPW 气象站当成建筑地址。
3. 确认建筑声明后，数据库事务一次性归档项目、归属、文件和待审证据。重复提交复用同一项目；数据库写入失败整体回滚。已提交的工程证据不能在收件箱中删除。
4. EPW 调用天气服务；IFC/DXF 调用已有空间识别服务，成功后停在人工复核。DXF 未知单位会阻断；候选默认层高/标高来自导入设置，并非测量结果。PDF 自动提取文字不等于已完成几何重建。
5. 在资料详情补充来源和使用许可，保存为新版本并重新待审；原文件与历史版本保留。完成必要工程复核后再进入真实仿真。

扫描 PDF 和图片现已接入本地 OCR 与原图校正，但文字提取不等于完成工程建模；DWG 仍只保留原件。详见 [OCR 实测](DOCUMENT_OCR.md)。账单/设备表目前完成结构清点，未自动完成列语义映射和能耗校准。

## 账号、数据库与后台

新工作区首个账号是管理员；用户名 3–32 位且必须包含字母，密码至少 12 位且含字母与符号，不接受重复字符弱密码。后续账号默认需要管理员生成的一次性邀请码（1–30 天）。邀请码在数据库中只保存哈希，明文只在创建响应中显示；可撤销，使用后失效。

已有账号保留原密码和项目归属；新注册规则不强制改写旧凭据。账号设置提供旧密码验证后的密码修改，撤销其他会话和原 API Token。停用成员也立即撤销会话与 Token，不能停用首个管理员。没有默认密码、自动生成正式测试账号、邮件验证或虚构密码找回接口。

`VRA_REGISTRATION_MODE=invitation` 为默认；`open` 是显式部署选项，现有多账号隔离测试采用测试进程内的 open 配置。专门的邀请测试移除该覆盖，实际核验默认邀请策略。正式部署前应在受控环境初始化管理员；本次仍只监听本机。

数据库新增表：`inbox`、`invitations`、`admin_audit`；`users.disabled` 增量迁移；SQLite `user_version=2`。收件箱文件在服务端 `inbox-files/`，归档后由原哈希关联。管理摘要不返回密码哈希、盐、会话令牌、API Key 或原文内容。业务 API 继续执行归属、CSRF 与同源检查。

原始资料解析完全在本地进行。选择外部 AI 服务后，工具仍遵循既有范围和显式计算授权；新增 PDF/文本预览及原文摘录会从发给服务商的工具上下文中移除。模型说明不作为核验后的工程结论。

## 验证与不足

最终本地完整回归：185 项后端测试及 6 项子测试通过；前端 30 项通过；Ruff、前端语法检查、生产构建及 OpenAPI 契约导出通过。完整后端日志保存在本机 `validation/intake-20261023/backend-tests.log`。这些检查不构成客户项目精度或生产部署认证。

- 实际 Edge：将公开 Duplex IFC、Golden EPW 和明确标注为合成资料的 PDF 同时拖入首页。5 个明确声明自动提取，三份文件归档；天气分析产生，IFC 停在“待人工复核”。随后通过页面生成邀请码、受邀注册，普通成员访问后台显示无管理权限。
- 公开输入重测：[原始结果 JSON](benchmarks/2026-10-23-intake/public-inputs.json)。Duplex：21 个候选空间，2.593 秒；Schependomlaan：100 个空间中 94 个不完整空间仍阻断，4.750 秒。时间为本机单次全流程测试值，不是性能承诺。没有改变源文件或跳过失败空间。
- EPW 使用哈希 `65041e11615dac66cfac8b2e3f83ea0297f42f20fc90ef3723a8241153a62e0b` 的 8760 小时文件，自动分析后仍需确认适用性；没有新增能耗精度结论。
- 可复跑脚本：`scripts/verify_intake.py`，要求用户提供两个公开 IFC 路径和全新隔离数据目录。原 IFC 不随仓库再分发；来源、许可及上一轮物理对照见 [此前实测](EMPIRICAL_BENCHMARK_RESULTS.md)。
- 回归覆盖：多账号隔离、一次性邀请/过期/撤销、弱凭据、密码修改、账号停用、旧数据库迁移、批次恢复、损坏文件保留、冲突、原件篡改、事务回滚、重复归档、来源修订、PDF/XLSX/EPW/DXF 实际解析、不同任务工具、外发文本过滤。

本次改善导入与使用流程，不等于完成商业交付。复杂 IFC 自动建模、任意图纸理解、真实客户账单校准、成熟团队权限、多实例运行及与斯维尔/广联达持证同题测试仍未完成。现有测试不能据此宣称可替代这些商业软件。
