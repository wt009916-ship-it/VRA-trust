# 施工进度与关键路径：限定范围验收

日期：2026-11-05；基线main 412b1d04ff6d899120239961163ead04931c9731。属于原路线工作包3的施工进度子批，不代表施工方案安全审查、现场调度或完整运维系统。

## 实现范围及调用链

前端施工进度表单/JSON导入 → ScheduleInput严格契约 → 确定性CPM、显式剩余工期情景及资源区间检查 → 独立schedule记录 → 当前来源核验 → UI/JSON/HTML。Agent增加schedule_list/read只读工具，不能编造工期或创建施工结论。

- 1–250工序，每工序最多50个前置关系；明确FS完成到开始关系及非负间隔，不接受自依赖、重复、未知工序或环路。拓扑排序输入次序无关。
- 连续经过日和明确第0日口径；零工期为里程碑，未知工期留空。尚无工作日历、节假日、天气、SS/FF/SF和负间隔。
- Decimal正反向计算最早/最迟开始完成、总时差、自由时差、关键工序及连接它们的关键关系。结果为十进制字符串；日数及资源数量最多6位小数，防止细微量被静默吞掉。
- 进度必须明确报告时点及工序状态；已完成必须有实际起止，进行中必须有实际开始，剩余工期可未知。拒绝未来实际日期、结束早于开始、与已报告前置完成关系矛盾的记录。未报告不等于未开始；不会由完成百分比外推剩余工期。
- 已完成保留实际区间；进行中完成日=报告日+显式剩余工期；未开始按报告日及已知前置预测完成安排。缺报告/剩余工期或实际依赖未验证时，完整预测完成日及偏差为空。
- 最多50种资源、每任务10种占用，按半开区间[start,finish)检查重叠，因此恰好衔接不算冲突。容量0表示不可用，null表示未知；输出超配区间、用量、容量和工序名单。没有自动资源调平；CPM工期不是受资源约束后的可履约工期。
- 输入工期、依赖、资源及进度来源均显式保留；项目、文件、证据、计算器变化使旧记录stale。撤回证据拒绝新建；原件和历史记录不覆盖。
- 可手工创建/编辑工序、关系、资源、进度，折叠工序表单，时间轴、历史快照、复制、JSON及HTML报告；导入保留原文件。草稿JSON下载入口已实现，本批未执行浏览器下载验收；无持久草稿恢复承诺。

## 缺陷记录

### SCH-001：极小资源需求被数值精度吞掉（中，已修复）

对应功能：资源超配检查。复现：资源容量1，时间重叠的B需求1、C需求1e-100，按原契约提交。预期：识别超过容量或拒绝不支持的输入精度。实际：原契约接受，40位Decimal运算把额外量舍去，返回checked_declared_resources且conflicts为空。证据：resource-precision-before.log失败、resource-precision-result-before.json实际输入输出。修复：资源数量限定6位小数，正需求至少0.000001；容量0仍合法，未知null。回归：1e-100拒绝，1+0.000001明确报告需求1.000001超配。建议：新增数值域统一明确量级与有效位数，不让显示正常代替边界验证。
