# 逐时热工独立交叉验证

本批使用新输入、新原生运行和预先保存的解析答案。公开参考与合成模型不能替代实楼校准。数值、日志及源文件哈希见 `validation/dynamic-thermal-20261107/`；可复算程序为 `scripts/verify_hourly_thermal.py`。

## 独立解与适用边界

合成房间 5×5×3 m，六面总面积 110 m²，室内恒温 20 °C。外侧温度为振幅 5 K、周期 24 h 的正弦函数，内外膜换热系数分别为 10、25 W/(m²·K)。没有太阳、通风或潜热负荷。墙厚 0.2 m、导热系数 0.5 W/(m·K)、比热 1000 J/(kg·K)，密度分别取 500、1000、2000 kg/m³。无热容量对照使用 R=0.4 m²·K/W。

令 α=λ/(ρc)，ω=2π/86400，γ=√(iω/α)。均质墙解析传递矩阵为：a=d=cosh(γL)，b=sinh(γL)/(λγ)，c=λγsinh(γL)。包括表面热阻后 B=b+Rse·d+Rsi·a+Rse·Rsi·c。采暖率独立解为 H(t)=110×[20/0.54−Im((5/B)exp(iωt))]。无热容量时 B=0.54。按声明时间步的末端点求小时平均；不是用引擎结果拟合答案。

预先容差为 max(1 W，解析负荷振幅的 2%)，倍率应用前判断。恒温条件温度误差限为 0.01 K。所有答案、容差和 IDF 在首个引擎调用前保存。重房间热容量的结果不等于自由漂移室温响应已验证；这里室温由理想系统维持恒定。

## 首轮失败及修正

最初使用 OtherSideCoefficients 的正弦选项，同时指定外膜系数 25。引擎输出为常温边界，三个输入均未通过。固定版本源码显示，9.0.1 的 `OtherSideCoefCalcExt` 分支直接使用常数系数，没有像 `OtherSideCoefNoCalcExt` 分支那样应用正弦系数。见 [HeatBalanceSurfaceManager.cc](https://github.com/NREL/EnergyPlus/blob/v9.0.1/src/EnergyPlus/HeatBalanceSurfaceManager.cc)。

修正方式是新建输入，使用显式逐时间步温度日程、常数系数1；保留原模型与失败输出，未改引擎或放宽容差。后续通用生成器又曾将 Floor 类型误作名称添加后缀，11个运行均被引擎拒绝；修正字段映射后重新生成另一批目录。两类失败均不计入通过。

## 全年与跨平台

本批每个平台新跑 baseline/R1/R2 三个全年公开参考，未重签旧物理运行。模型包含5个房间和1个吊顶夹层，共6个分区；逐时数据完整覆盖8760小时。浏览器另起真实运行，采暖/制冷同时峰值分别为15023.527897 W、14414.848720 W，原生环境及日期随结果保存。

`cross-platform-v2.json` 记录首轮差异。两平台各自生成输入，动态判定相同，但最大峰值差约0.002502 W。随后哈希核对发现两平台生成的日程及解析答案不是逐字节相同，因此该轮不能归因于引擎平台差异。将 Windows 已冻结的全部输入、答案与容差原样交给 Linux 后，新跑11个场景：9通过、2粗步长未通过，所比较的峰值、误差及温度统计差均为0；详 `native-linux-exact-v1.json`、`cross-platform-exact-v1.json`。原失败和输入差异保留。

全年参考模型字节一致，R1/R2全年制冷峰值差仍分别约0.00002582/0.00003717 W，预设的1e-6 W严格一致性判据未通过，未调宽判据。它与工程解析容差检查是两件事，不能混报为完全逐位复现。

Linux上三份约13.2 MB SQL的单次解析观察为0.426～0.458秒，包含哈希核验。这不是负载容量、并发压力或生产性能承诺。

## 明确尚未验证

自由漂移室温、复杂多层非均质构造、太阳及长波辐射耦合、渗透与通风、潜热/除湿、一般设备容量、极端气象适用性、实际建筑与当地设计规范仍需独立资料及测试。脚本完成退出码仅表示完成记录流程；须阅读各算例 `status`，不能将整批退出0等同于11个数值场景全通过。
