## 结论

当前软件是部分流程已验证的工程原型，可以做有明确输入和人工复核的有限方案试算、结果追溯、材料候选比较与 API/MCP 调用。不能承诺任意图纸自动形成可计算 BIM，也不能承诺已经达到面向客户的商业交付水平。

本次外部住宅 IFC 的完整“原文件 → 可计算模型 → 能耗”验收**未通过**。成功读取 21 个空间候选，不等于完整建筑转换成功；系统拒绝继续计算，真实引擎调用数为 0。此前简单测试模型和官方参考 IDF 的成功不能覆盖此失败。

独立诊断在原 IfcOpenShell 三角网格的绝对标高 3.5、4.0、5.0 m 处取水平截面。两组卧室/楼梯在六个截面对照中的原始重叠面积均为 0；导入候选的两组棱柱在相同高度均重叠约 0.1531744 m²。楼梯底面约 3.804 m²，上层截面约 3.54127 m²；当前导入器把底面贯穿整个高度，未保留变化截面。

这定位了本例的转换限制，不是完整 IFC 合规认证。审计脚本另保存的网格体积计算没有完成闭合性/面朝向认证，不能当作几何精度百分比。IFC 属性中的 GSA BIM Area 与空间内底面积也不是同一面积口径。

当前 IFC 导入只提取 IfcSpace 的底面、最大高度和 GlobalId，不转译该文件里的墙体构造、实际窗门及空间边界关系。即使修正了重叠，也还需要解决内外墙、楼板邻接、非空调空间和热工参数映射，不能只让校验通过就宣布能耗准确。

|LLM/视觉识图|配置和协议、候选验证代码已有|没有真实服务商 Key 的联网识图验收；不是已验证的 AI 自动建模能力|
|报告与失效处理|同源 JSON/HTML/PDF、原始输入/SQL/ERR；改因子仅重算碳、撤回证据抑制受影响结论已有实测|不是签章成果、节能审查合规证明或实测精度认证|

80 m² 例子的两次运行总量为 8422.20 和 8461.85 kWh，属于假设条件下电力及理想供冷供热的分载能汇总。它们不是这个 Duplex 的结果；不能称为住宅实测能耗，也不能把第二方案宣传为节能。

当前核心功能是：整理改造依据 → 用完整 IDF 或受限几何形成情景 → 调用真实引擎 → 比较有来源的材料候选 → 保留结论和输入的版本联系。材料仅按已实现的热物性建模；稀土材料优势、相变潜热和现场节能收益尚未验证。

现在能够具体展示的产品价值：

尚不能证明我们比两家软件更准、更快、更省钱，也不能证明上述机制在竞品中不存在。更合理的近期定位是既有建模软件后面的改造方案复核/决策辅助工具；这是基于当前范围的产品判断，尚未经过客户付费验证。

## 本次失败给出的下一步验收要求

1. 先修复并回归这个**完整且未删减**的 Duplex：变化截面楼梯/走廊应拆分为正确热区或明确拒绝，按源 GlobalId 报告丢失/简化情况。
2. 再验证墙窗、房间邻接、楼板厚度间隔、非空调空间和面积口径映射；校验通过不能代替这些工程检查。
3. 图纸/PDF 路径另选外部真实样例，记录房间漏检、误检、几何误差和人工修正时间；接入真实视觉服务后再统计识图表现。
4. 取得温工认可的手工建模基准，在同一建筑、天气、构造、设备、时刻表下对照；没有这个基准，不报告精度或节时优势。
5. 达到业务验收、实际用户操作和部署运维要求后，再作可售产品判断。此前的单元测试/CI 通过不等于这些验收已完成。
