# 计算保存一致性与失效原因追溯

本批修复六类专业计算在计划校验和实际保存之间的来源修订竞态，并补齐五类计算缺失的失效原因。热工、阶段碳、材料成本、梁分析、施工进度、设备规则共用事务内来源核验。计算公式没有改变，历史记录不重写。开发复评保持75/100；95+目标尚未达到，未扩大训练。

## 缺陷与复现

### CP-01：旧计划可能绑定新项目或依据版本（高）

- 对应功能：六类Agent计划执行及专业计算保存。
- 复现：冻结计算计划；在`resolve`校验返回后、业务服务`save`读取项目之前，另行修订项目声明；继续执行原计划。隔离测试用确定性插入点重现这个时序，没有修改原型数据。
- 预期：拒绝旧授权快照的写入，提示提交新的已复核计划。
- 修改前实际：六类均未拒绝，保存时读取新修订并将原计划绑定到新版本。原有检查只覆盖“校验前已变化”，没有覆盖随后到达的修订。
- 证据：`tests/test_calculation_provenance.py`；本地`validation/calculation-provenance-20261107/before.log`的六项竞态失败。
- 修复：在SQLite `BEGIN IMMEDIATE`事务中同时检查计算捕获的项目、依据版本，以及Agent冻结的授权版本；原件重新核验，通过后才在同一事务插入。来源变更抛出可识别拒绝，不留下新计算记录。
- 验收覆盖：六类校验后项目修订、六类校验后依据修订、六类计算期间项目/依据修订、独立连接写入竞争、插入后异常回滚、正常保存。来源在提交成功后再次修改时，记录按历史版本保留，当前读取返回失效。
- 范围：原件由应用API不可变并在保存/读取时重哈希；不宣称能抵御有本机磁盘写权限的攻击者在最后一次哈希后直接改文件。

### BP-03：失效原因丢失，模型可能误归因（高，服务端原因链已修复）

- 对应功能：阶段碳、采购、梁、进度、设备记录及Agent正式限制说明。
- 复现：保存记录，修订项目声明，再读取记录并提交`professional_limit`。
- 预期：返回项目版本从1到2的已观察变化，当前结果为空；方法适用范围不得冒充失效原因。
- 修改前实际：五类只返回`stale`，没有原因；前批真实4B曾误将进度失效解释为资源未调平。原始模型失败见PR38证据，未覆盖或删除。
- 证据：修改前测试五项`stale_reasons`缺失；本批冻结真实模型输入与响应另列证据索引。
- 修复：六类统一返回`stale_reasons`及结构化`stale_details`。区分项目修订、计算器版本、依据修订/撤回/缺失/归属不一致、原件版本或完整性失败。原因带对象ID及可用的新旧版本，传播至业务记录、同源报告、模型投影、正式限制交付与界面。
- 验收覆盖：项目与依据修订、撤回、计算版本变化、CSV破坏；失效数值不可正式交付，历史存储内容保持不变。
- 限制：结构化原因由应用核验；模型自由文字仍不作为工程依据。小样本复测通过不等于一般幻觉已消除。

### BP-UI01：编辑同一项目后执行模式被重置（中）

- 对应功能：项目编辑与Agent输入区。
- 复现：选择本机模型，保存建筑资料，再观察执行模式并提交任务。前批真实浏览器曾因此误运行本地确定性流程。
- 预期：保留同一登录会话、同一项目的模式选择；不延续计算授权。
- 修改前实际：重绘表单默认选择`local`，导致执行路径改变。
- 修复：只在内存保存当前用户/项目的模式偏好；切换项目或退出登录清空。重新渲染后的计算许可仍默认关闭。配置状态刷新不改变模式，也不把配置可用冒充模型连接成功。
- 证据：`frontend/tests/agent-mode-status.test.js`及本批浏览器记录。真实浏览器结果以证据索引为准。

## 版本与验收纪律

新增来源核验模块纳入每类计算版本摘要。旧版本记录可能因此保守失效，保留其原始hash、输入、数值及时间，不改写历史让其“通过”。没有重跑全年EnergyPlus，没有宣称获得新的节能或结构安全工程验收。

修改前12项定位测试为11失败/1通过；第一次相关回归90通过，扩展相关回归238通过（最后补入的6项授权依据竞态纳入后续全量）；前端62通过。最终Windows805通过/25跳过、Linux814通过/16跳过，均6子测试；4B/8B各4旧题+2新题通过预设核验（12任务37请求），浏览器另2任务6请求。3个浏览器脚本断言/定位错误保留：不必要地强制选择批量工具、查找只读任务中不存在的计划区域、将summary误定位为button；修正后完成模式/授权/双失效报告验收，页面异常0。8B旧题B04还输出过JSON形式的finish文字，未当作工具调用计分。完整平台、真实模型、浏览器结果由[证据索引](CALCULATION_PROVENANCE_EVIDENCE.json)记录，失败与脚本错误同样保留。双平台和推理部分并行运行，耗时不能用于平台或模型性能排名。

## 后续优先级

1. 缺失记录的明确交付与恢复：区分整个项目没有记录、最近6条列表未覆盖、计划执行失败；不允许猜ID或把无数据包装成任务完成。
2. 一般来源提示词注入、多专业自由需求完整覆盖、纯文字授权条件的产品化约束；继续真实模型对照，不增加训练掩盖控制缺陷。
3. 扩展复杂CAD/BIM与破损图纸、不同气候/设计工况参考基准；公开参考和实楼校准分开。用户暂无实楼资料，后者仍待验收。
4. 能力门槛达到有证据支持的95+后，再扩大数据训练并整体改善前端辨识度、字号、密度和输入体验。本批模式修复不代表视觉改版完成。
