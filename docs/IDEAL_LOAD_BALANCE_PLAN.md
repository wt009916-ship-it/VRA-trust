# 下一能力批：理想空调显潜热及新风分解

这是下一批的实施范围；尚未运行新增算例、没有产品通过或加分声明。基于IFC梁产品b40d25b继续，目标对应B03及原独立热工/原生SQL未满项，不能重复计算已有显热收益。

先冻结独立热量和水分平衡答案，保留声明边界；核对原生9.0.1输出和实际SQLite字典，再开发来源绑定的解析/API/报告。第一批只支持明确ZoneHVAC:IdealLoadsAirSystem；设备实际效率、耗电和选型仍不推断。

1. 分别读取区内、供风、新风和热回收的显热、潜热、总量及实际空气质量流量，不能把不同边界的总量相加重复计入。标准输出含主动运行条件，零值不等于已经验证全天室外负荷为零。
2. 验收先从无新风、有湿负荷的单区开始，再加明确新风和已声明热回收控制；新几何/日程/独立水分与能量答案须在首轮运行前冻结。冷暖方向、时间平均、乘数、期间与同步峰值明确核对。
3. 原生质量流量、湿度及焓差只用于核对输出含义；独立期望不能反过来从同一原生结果拟合。输入不满足稳态或控制前提时保留失败，不调容差制造通过。
4. 缺变量/单位错误/重复键/不完整时间轴/未知设备映射不得填零；无此系统的模型明确不适用。新分析不可用不伪造年度结果，也不改写旧模型、SQL或manifest。
5. 单元/API与真实原生新输入分别留证；浏览器仍按用户选择暂缓。出口必须是应用可读取的真实结果与报告，不能只交付探针脚本。最终按原子项证据复评，不先承诺分数。
