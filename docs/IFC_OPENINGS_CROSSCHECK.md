# IFC 开洞独立交叉验证

基线中的全覆盖洞口错误在Windows直接解析、隔离API及非root Linux同字节输入中均复现。独立答案采用轴对齐盒的坐标分割并集，未调用产品网格函数生成答案。二维布尔路径返回24 m³；关闭该路径得到空网格。空网格不是独立证明的零值，产品保持未知。

八个冻结案例覆盖穿洞、重叠洞口、部分穿出宿主、完全在外部、相切、两个相同洞口实体、重复开洞关系和全覆盖。六个有效数值检查通过，两项按各自拒绝条件通过；Windows/Linux回执一致。另有37项专项和完整回归，统计见[交付](IFC_OPENINGS_DELIVERY.md)。

公开模型SHA256为b347a2c8aa8fff6db896a4417a9c50c22ac0ccd7c5cfc22b99b8d29336c606ed。原始STEP字段独立算法校验108个无开洞棱柱及21项声明值；295条声明空间关系并非几何邻接验证。切换布尔路径后，只有#5903的有效体积状态发生变化。其宿主矩形约2.089×0.124×3.388 m，洞口约0.864×2.032×0.124 m。通过原始轴向映射和Decimal区间交集：

- 宿主与洞口交集0.21770035199999798783232 m³；

- 双平台实际0.6599136160000011 m³，绝对误差1.064225288e-14 m³，小于1e-10 m³容差。
