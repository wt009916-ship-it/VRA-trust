# 整包投资比选

入口：打开项目 → 材料与决策 → 整包投资比选。

用于改造前期比较相同工程范围的完整采购/施工方案。它连接工程量、具体产品版本、工程适用性、费用及材料阶段碳账。原有材料热工研究仍独立保留；整包比选不会把几个单材料仿真的节能量简单相加。

## 操作

1. 登记并复核工程量、报价及产品检测等项目资料。假设、AI推断和未复核资料不能充当采购依据。
2. 下载UTF-8 CSV模板，填入部位ID、名称、数量、单位、共同性能要求、来源ID及定位，再选择文件导入。也可逐项添加。一个工程部位只有一个共同工程量，各包沿用同一范围。
3. 添加常规方案包，再复制为替代包修改产品。每个部位记录产品型号/批次/版本。一个包不能同时选两个互相替代产品，漏掉部位会列为缺项。
4. 填各部位的材料/设备、安装、拆除清运、脚手/措施及停用/搬迁费用。金额是**覆盖该部位全部工程量的含税总额**，不是单价。每项必须有报价来源及定位；不适用填有依据的0元，空白保持未知。有截止日期的报价须填写有效期。
5. 核对同等功能、防火、耐久环境、现场施工四类适用性，分别关联依据。判断只是工程师声明，不等于自动读懂报告或通过第三方认证。
6. 可补充年维护、寿命、每次完整更换费用及统一阶段的材料GWP。未知字段不会被默认成0。GWP单位须与共同工程量一致；跨kg/m²/m³换算须先取得相应数据，本功能不隐式转换。
7. 先检查，再保存比选与来源版本。可在历史中打开结果或载入副本修订，原记录保留。导出JSON工作文件可恢复输入；HTML复核报告包含费用拆解、缺项、逐年账本和输入/来源快照。

CSV表头：

```csv
scope_id,name,quantity,unit,requirements,evidence_id,locator
```

单位为`kg`、`m2`、`m3`、`item`。支持UTF-8 BOM、引号及字段内逗号；空表、重复ID、错误列数、非有限/非正数量会被拒绝。最多40个共同部位、12个方案包；CSV/JSON工作文件界面上限200KB。文件导入先进入工作区，不自动保存。

## 结果口径

|字段|计算或含义|
|---|---|
|初始投资|每个完整部位的五类已声明费用相加。工程量无复核来源、漏部位或漏任何费用，则整包金额未知，不能判预算内|
|预算|仅按已知完整初始费用核对上限；适用性缺口另列，便宜不等于可采购|
|已声明支出折现|初始投资 + 各年末维护费折现 + 寿命整数倍且小于比较年限时的完整更换费用折现。没有对应输入则保持未知|
|初次材料碳|各部位共同工程量 × 同单位GWP，统一声明为A1–A3或A1–A5；任何部位未知则整包未知|
|状态|待补证 / 超预算 / 待工程师复核。未自动选择获胜方案或签章|

折现支出不包含未填入的能源费用、融资、残值、收入；它不是完整投资净现值。材料碳不包含后续更换、运行及未声明阶段，不是完整LCA，也不是可售碳信用。寿命与费用为输入声明的未来情景，未证明实际寿命。

来源修订、原件变化、规则变化及报价过期会使当前报告失效，旧记录保留。载入副本并补齐当前来源后才能重新形成结果。修改工作区后会提示旧结果仍对应上次检查，报告导出绑定上次结果的输入快照。

## 可集成接口

- `POST /api/projects/{project_id}/sustainability/package-quantities`：`text/plain` CSV → 待复核共同工程量，不保存。
- `POST /api/projects/{project_id}/sustainability/packages/preview`：结构化整包输入 → 计算与缺口，不保存。
- `POST /api/projects/{project_id}/sustainability/packages`：保存输入、结果、证据快照及规则哈希。
- 既有`sustainability`列表与详情接口读取历史、核对失效；工程助手可通过既有只读工具读取记录。

仍需当前会话、项目归属和写请求CSRF；跨账号拒绝。测试及限制见[本轮验收](benchmarks/2026-11-01-package-comparison/README.md)。
