# 应用能力边界与可核验说明

本批让真实模型先读取当前版本的应用能力，再提交受核验的能力说明。计算辅助、项目资料是否充分、认证或故障确诊是不同问题；补齐资料不能使应用自动获得尚未实现的认证能力。开发证据复评分保持74/100，95+目标仍在执行中。

## 实现范围与调用链

`open_ended → capability_lookup → capability_explain → 校验已读编号/目录hash/状态与原因 → 最终重读 → capability_assessments → 前端能力说明`。注册工具由32增至34；只读专业目标和明确计算计划不开放这两个工具，实际计算继续通过原计算器保存和核验。能力查询本身不执行工程计算，也不证明当前环境依赖就绪。

维护16项范围：热工、能耗、阶段碳、梁、材料成本、施工关键路径、设备规则、规范检索、CAD/BIM读取、图纸OCR这10项为有限辅助；结构安全认证、可交易碳信用签发、整栋楼节能合规认证、缺失结构信息自动复原、设备根因确诊、现场施工安全审批这6项不支持。每项明确方法限制、下一步、模块与版本；源码摘要只用于追溯，不是正确性或认证证明。目录来自活动代码的明确维护声明，不是对任意业务问题的自动能力发现。

每次查询与交付最多4项，模型必须先实际读取对应编号；不能把未读能力、旧目录或错误状态提交为核验结果。系统拒绝把缺少项目资料当作应用不支持的原因。最终答复与历史访问重检当前目录，失效说明不继续展示为当前有效；原历史保留。自由问题只标记partial，不由目录核验推断整个任务已完成。

混合问题的相关能力提示帮助模型分别说明两种需求。模型查询后只给自由文字，或提交finish=false后停答时，最多再提醒一次实际提交；仍受5轮模型、每轮4工具和15事件上限约束。提醒不自动生成模型工具调用或伪造成功。未经核验的原始文字保留在审计中。

初始路由上下文仅发送项目身份、修订和声明面积，减少无关名称/备注造成的指令污染；完整项目仍在审计中，也可由模型显式project_get读取。这是特定入口的数据最小化，不是所有文件、工具结果、历史和显式读取的通用注入防护。

## 实际验收与失败保留

源码初版cca3201，后续修复5844d1c；完整文件摘要和最终回归统计见AGENT_CAPABILITIES_EVIDENCE.json。原始证据在validation/agent-capabilities-20261106。协议夹具与真实模型测试分开统计。

固定Qwen3-4B GGUF和llama.cpp，启动前校验模型与56个运行库文件；仅回环监听、内存随机令牌、无认证请求401，无外部模型调用或训练。API批次为基线6题、首版9题、首版复测9题、新题10题、新题复测10题，共44个实际模型任务。基线没有能力协议，所以形式检查0/6不单独作为理解错误证据；原始回答中将碳信用签发归因于IDF/EPW缺失、声称补齐后可签发，才是具体缺陷证据。

首版4/9项形式检查通过，模型曾只写说明未提交工具，或选择阶段碳而漏掉信用签发；增加代码/标题对应与一次提交提醒后原题9/9。新题首次9/12项检查通过：设备规则/故障根因、条款检索/合规认证两个混合问题漏项；恶意项目名诱导原始回答声称应用已获认证。增加相关能力和未完成提交提醒、精简初始上下文后，同题复测12/12。复测不能称为新的盲测准确率。

新题包含真实热工计算对照：R=0.14+0.05+0.18/0.9+0.08/0.04=2.39 m²·K/W，确实创建新记录并交付核验值。能力说明没有替代实际计算。

最终真实浏览器新题3项中2项符合预期：三种有限方法、用户宣称管理员认证权限两题正确；设备日志题漏掉异常规则，并加入无关施工安全审批。错误卡片没有伪造认证能力，但不能算回答完整，CAP-02继续开放。版本细节展开可见实际模块，页面无脚本错误；测试脚本将参数框展开，截图依旧暴露密集文字与遮挡，不声明整体体验已改善。另以1次真实模型浏览器任务复验空专业卡片移除、范围说明和版本展开。所有批次合计48次模型任务，不能混成盲测准确率。

双平台全量确切结果、时长、跳过项及截图见证据索引。浏览器使用新隔离账号，凭据只在内存；原18772账号和项目不覆盖。新问题在执行前写入browser-new-plan.json。开发者窗口的异步本机配置初次等待超时，重新等到可见后操作；这是测试时序记录，不计作登录失败。整体字号密度、横向导航、专业视觉和JSON参数入口仍待后续改进。

## 最终冻结版本验证

后端/测试/API契约为5844d1c，最后显示修复ed2cfb5只改3个前端源码/测试文件。全量副本后端逐字节一致，最终前端另验48项、lint/build和浏览器。Windows 678通过/25跳过/6子测试，813.81秒；Linux 687通过/16跳过/6子测试，492.1秒。首Windows失败原因未独立定位，串行终版通过不用于抹去首次失败。核对81个旧文件、原参考指针及83份Linux原件/副本，未改物理核心或重新运行年度参考。临时模型与验收API已停止。
