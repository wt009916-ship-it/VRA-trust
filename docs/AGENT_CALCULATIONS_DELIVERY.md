# 明确参数计划 → 实际计算 → 核验交付

本批让智能体实际创建热工、阶段碳和材料成本记录，复用三个已实现的计算器。用户提交带类型的完整参数，模型只选择计划编号；应用保存新记录、读取当前结果并核验交付事实。不是让模型自行设计工程参数，也不是任意复杂任务自动完成。八维开发证据复评为74/100，仍未达到95+。

## 使用与调用链

在工作台展开“本次计算参数”，输入1–2项JSON数组；每项包含唯一的 `plan_key`、`kind`（thermal/lifecycle/cost）和 `input`。参数分别复用 Assembly、Inventory、Estimate 的现有契约，阶段碳与材料工作台导出的草稿可作为 input。选择自由提问、真实模型模式并勾选允许计算。纯本地工程流程、只读目标、未授权、重复编号、超过两项、非法数值或单位均拒绝受理。

`Chat.calculation_plans → typed validation → deep-copy/snapshot → calculation_execute(plan_key) → Thermal/Lifecycle/Costs.save → corresponding read → professional_deliver → final current read`。工具注册共32项，但有计划的任务仅提供执行、相应专业读取、交付和项目读取；其他写工具及旧记录不能替代计划。无计划的自由问题仍沿用既有工具范围。

模型参数只有plan_key的枚举，没有工程参数修改入口。服务器保存输入与摘要，绑定提交时的项目修订、关联证据修订/hash和原件身份；执行前再次检查，随后由原计算器继续做地区、面积、来源及有效性校验。关联证据不等于独立认证，未关联来源的参数仍是用户声明。模型只获得计划编号、专业、名称和随后读取的事实投影；完整输入保存在需账号与项目授权的本地审计记录中。名称及来源文字不作为指令。

同任务同计划重复调用复用已经保存的结果；写入结果不确定时不自动重试。跨任务没有幂等合并：再次提交会创建新记录，界面明确提示。两份计划不是数据库原子事务，后一份失败时前一份保留，进度显示“已创建记录·尚未形成有效交付”和“未执行”。历史授权不延续，旧计划不自动重跑；当前正式事实继续重检，失效结果不复用。进度“当前结果已核验”也不代表自由问题覆盖完整；整体答复仍为partial。

保留5轮模型、每轮最多4工具及15事件上限。正常双计划可同轮创建、同轮读取、同轮交付，再由流程分别复核；协议测试为12事件。模型可漏执行、提前结束或耗尽预算，不能据此把未执行计划改为完成。最多两份是本批明确支持范围，不声称任意多工具规划已经达标。
