# 分区设计显热负荷独立交叉验证

本批固定EnergyPlus 9.0.1，检验原生ZoneSizes中计算显热W、用户调整显热W、设计日/峰值时刻、倍率和报告传递。模型是独立合成输入及公开五区参考，均不称为真实建筑校准。物理源码摘要为`811cc91edfdfbed58f78d4b69bb52cbfde20a51b22fdcc68545a2b868d29d6ab`，解析器摘要为`ce823df8d3adb62aec3e0fefd5a286226f4154046df95603893c81f3350c904d`。

## 独立基准与边界

自建5m×5m×3m封闭单区，六面总面积110m²。各面具有相同材料热阻；指定内外对流膜系数10和25W/(m²·K)，没有太阳、人员、新风或渗透。冬季室内20°C、室外−10°C；夏季室内25°C、室外35°C。期望值在执行前用独立稳态热平衡计算：

`Q = 110 × |Ti − To| / (1/10 + R + 1/25)`。

R=2m²·K/W时，供暖1542.056074766355W，制冷514.018691588785W。这些是本模型的规定边界，不是实际墙体或当地规范默认值。每次运行前固定容差为`max(1W, 期望值×0.5%)`，没有按输出修改容差。

计算负荷与用户调整负荷分别核对；用户设定冷热裕量时，计算值仍对应原热平衡，调整值对应相应裕量。分区/分组倍率只在独立期望值应用一次，核对原生结果已包含倍率，产品不再次相乘。

Windows和非root Linux各7次独立启动原生引擎，每次4项数值核对（冷热×计算/调整），各28项通过。

## 原生结构、单位与传递

38项解析反例覆盖缺表、重复行、缺冷热配对、负值、非有限值、缺值、未知版本、单位冲突、HVAC表格差异、设计日及峰值日期不绑定、倍率、零负荷和缺失区分。投影夹具来自实际原生SQL，但夹具测试不是新的EnergyPlus执行。

原生SQL与固定版本源码绑定：`ZoneSizes.CalcDesLoad/UserDesLoad`按W读取，HVACSizingSummary存在/已请求时交叉核对两位小数W单元格，容差0.011W。没有请求该表时明确记为`not_requested`，不将其记为通过。[EnergyPlus 9.0.1 SizingManager](https://github.com/NatLabRockies/EnergyPlus/blob/v9.0.1/src/EnergyPlus/SizingManager.cc#L4008)、[SQLiteProcedures](https://github.com/NatLabRockies/EnergyPlus/blob/v9.0.1/src/EnergyPlus/SQLiteProcedures.cc#L1689)支持字段语义；源码下载摘要和SQL实际结构检查另留证。网页中的旧字段列表不覆盖原生版本证据。

双平台各一次认证API真实全年参考运行得到10条负荷，原生result与同源报告一致；篡改模型绑定并同时更新普通文件摘要后仍被业务绑定校验拒绝，返回failed/null。另一次浏览器真实运行中，10条kW显示与原生W在显示舍入范围内逐项核对；7页PDF、JSON与ZIP的28个manifest文件校验通过，负荷行同源。撤回复核后指标及负荷不可用，原件摘要不变。

## 尚未证明的范围

本批不输出全楼同时峰值、潜热总冷量或完整设备容量，不证明设计日统计来源、当地规范适用性及全部原生位置覆盖逻辑。公开五区模型验证了调用、来源与传递，并没有独立的完整建筑负荷金标准。动态气候、真实账单校准、现场工况与专业工程师验收仍待完成；工程评分不能因原生引擎运行成功自动满分。
