# 原生任务父进程死亡约束 · 2026-11-06

本批从 PR #25 的 `140ab6436501d036dfd475c56b0a0e3dec41c538` 出发，修复调用者强制退出后原生任务继续运行的问题。实现提交为 `bc5ec0a9c847f6029ae0e6c210502dae2d18c88b`。本批是进程链生命周期增量，尚不代表完整 ASGI 崩溃恢复、临时文件回收或生产灾备完成。评分保持70，证据索引为 PARENT_LIFETIME_EVIDENCE.json。

## 先复现，再修复

`tests/lifetime_probe.py` 由外层工具创建全新测试目录/Windows AppContainer，启动只写合成 ready 标记并等待60秒的真实隔离子进程。模拟调用者执行产品 `execution.supervise`。从私有监督回执获取进程身份，在终止调用者之前持有 Windows 进程句柄 / Linux pidfd；观察与最后清理均使用这些稳定内核对象，不依赖再次查找PID。未强杀正式服务、未扫描清理其他任务目录。

修复前，Windows LPAC、非root Linux Landlock/seccomp 两平台均观察到：调用者被强制结束2秒后，监督器和原生子进程仍在运行。原始结果为 `validation/parent-lifetime-20261105/baseline-windows/observations.json` 与 `baseline-linux-v2/observations.json`。外层验收工具随后清理自己的进程和新建目录；这不是原产品自动回收成功。

## 实现与适用边界

Windows调用者保留匿名管道的唯一写端；监督器启动时检查管道并开启阻塞读取线程。EOF、异常字节或读取失败均导致监督器退出，既有 Job 的最后句柄随之关闭并终止原生子进程。LPAC启动代码改为给原生进程一个新的只读 NUL 作为stdin，只继承限定的三条标准流。原生子进程无法持有调用者管道的写端来延长监督器寿命。Job关闭的系统行为见 [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

Linux在监督器启动及原生进程preexec中各设置一次 `PR_SET_PDEATHSIG(SIGKILL)` 并回读，设置后核对实际父进程，拒绝父进程已退出的启动竞态。监督器保持单线程进入现有隔离preexec；未在Linux隔离前启动Windows式监视线程。内核契约针对创建进程的父线程；该线程提前退出也会终止任务。fork不继承该设置，特权exec/身份变化可能清除设置，因此必须逐代设置，并沿用普通只读运行库、非root、no_new_privs和默认拒绝的seccomp；本产品不能拿此机制支持任意特权程序。[Linux man-pages](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)

成功回执必须具备本平台生命周期字段；Linux原生隔离回执还必须绑定实际监督器PID。缺失/错误字段即使子进程返回0也拒绝成功。生命周期模块进入物理与解析版本哈希；新物理身份为 `6850835e1dde664e317dbd2bcbe32b04d1a8c95fa21f9578768712723c42102b`。旧记录仍失效，不改写旧manifest。

该机制不等于硬磁盘额度、Windows映射内存额度、系统挂起时的有界响应或无限后代进程治理。生产解析器/引擎仍必须通过现有隔离边界，不能以非隔离测试分支宣称任意程序树安全。Windows线程调度和内核终止存在延迟，单次观测耗时不是SLA。

## 验收与失败保留

新增10项测试覆盖调用者强杀、监督器强杀、恢复运行、缺失或伪造回执、没有私有管道的启动拒绝、Linux父身份不匹配和stdin确实为EOF。真实隔离强杀测试先由子进程读取stdin并写ready，再终止上游，因此也验证LPAC子进程没有继承存活管道。各平台跳过项单列，不计通过。

首轮专项：Windows35通过、1项Linux专属跳过；Linux35通过。Linux最终源码快照全量541通过、18跳过、6子测试通过，285.84秒；18项中包含6项未生成默认参考索引的旧NativeEvidence用例，另行实际执行的25项新EnergyPlus参考/取消/恢复验证全部通过，不能把这6项跳过写成通过。

Windows最终在同字节源码独立副本全量544通过、15项平台跳过、6子测试通过，563.88秒。Windows也独立执行25项新EnergyPlus参考/取消/恢复核查并全部通过。两平台三方案年能耗均为57193.23、55715.19、55592.10 kWh，面积927.20 m²；由原生SQL单元格和Decimal交叉验证。Windows另核对公开Duplex 295产品/空间关系、108棱柱和21声明量；公开旧图仍是12个预选标签正确10个、43候选，噪声合成图仍有错误文字，不宣称识别率改善。

最终合成调用者强杀复验：Windows监督器与子进程均退出，观测约0.016秒；Linux约0.0033秒。每个只是一次样本，不作性能或最坏时间保证。外层验收工具随后回收自己创建的staging/profile，不能将该字段当作产品强杀后自动回收。远程检查的精确提交与最终合并身份另见索引及本地release回执。

PR #26首轮精确提交 `4b58b715ef934868cb9cd5d0106f09bd2baedc72` 的push/PR六项检查全部成功。两份后端原始日志均541通过、18跳过、6子测试通过，分别226.60/159.20秒；前端和契约检查通过。日志与SHA已留存，远程没有真实EnergyPlus验收，不能替代前述本机双平台参考运行。补入该远程证据的最终文档提交仍需六项检查成功后才合并。

Windows第一次全量为2失败、542通过、15跳过、6子测试通过，639.28秒。两个失败均来自原目录的旧参考索引：源码变化后比较与碳重算正确拒绝复用旧物理结果。随后保留旧索引/报告及全部旧文件SHA，再尝试新建参考运行；原开发 `runs/` 已触发归档容量保护，系统拒绝新运行。未抬高额度、未删除旧运行、旧参考索引未改写。最终在新的公开源码快照及空运行目录内建立新参考链，继续全量验收。原失败日志、容量拒绝记录和旧索引副本全部保留。

Linux首次基线探针在NTFS挂载上不能chmod而在启动调用者之前失败；移至既有非root ext4验收目录后真实复现成功。复制日志时copystat同样不被挂载支持，数据字节已复制；后续只复制字节。没有把环境失败或证据复制失败计为产品通过。

前端源码未变，32项测试通过，构建和语法/契约检查通过；构建仍提示大于500kB的分块，未声称已优化。现有隔离UI服务在活动仿真/Agent/Search均为零后正常退出（码0），随后于同一本机地址启动新版本，健康检查成功。这不是新的浏览器业务验收：页面仍需登录。普通登录已获授权；从历史恢复并暂存测试密码的具体方式此前被自动审批拒绝，尚待补充授权，未重试或绕过。
