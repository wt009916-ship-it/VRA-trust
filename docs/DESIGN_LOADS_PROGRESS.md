# 设计日与分区显热负荷：候选实现与验收进度

## 实际实现

`backend/design_loads.py`从固定EnergyPlus9.0.1原生SQL读取分区计算显热负荷、用户调整后负荷、风量、峰值设计日和时刻、分区及分组倍率。它核对原模型设计日与分区名称、原生单位定义，并在原生HVAC表格存在/已请求时检查W单元格。没有所需信息、版本不支持、错误值或冲突时，负荷行是null，原因可见；不从全年能耗推算峰值。

`backend/core.py`将该回执接入真实运行和当前有效性检查，绑定模型、SQL、天气及解析器摘要。物理版本更新会使历史运行保守失效，历史manifest不改写。前端报告页、同源JSON/HTML/PDF和证据ZIP使用相同字段。界面/PDF最多展示100行并明示完整JSON，不把隐藏行计为零。

不输出全楼同时峰值，不再次乘原生已包含的倍率，不把显热称为总冷量或设备容量。IDF声明位置和EPW站点分开展示；坐标相近不是设计日来源证明，坐标不同时显式提示。设计日统计来源和项目适用性仍需专业复核。当前没有把所有原生位置覆盖逻辑独立核验为有效站点绑定。

## 后续与评分

真实模型首轮发现DL-003（高）：`inspect_results`模式仍提供`professional_read_many`，但此模式没有专业记录候选，生成`record_ids.items.enum=[]`。原生llama.cpp在推理前拒绝该JSON Schema，4B三次真实请求均失败，尚未执行分页。`live-4b-v1.json`及原始服务日志保留。修复把“无候选就不提供批量工具”判断移到所有任务模式共用位置；预期任何已提供工具的enum非空，且不把不存在的记录伪装为候选。新增结果/证据/热工核验模式的动态Schema回归；需重新进行真实调用。该问题是既有模式集成缺陷，不能归咎为模型幻觉。

DL-004（高）：空枚举修复后的第二轮3次4B调用进入推理请求检查，但原生服务分别报告12824、12812、9098 tokens，超过已配置8192。应用64000字符上限不能代替模型token窗口验证。初始Gate/证据/天气重复且提供无关专业工具；本地模型没有执行任务，记录于`live-4b-v2.json`及服务日志。修复限定已有运行核验的只读工具集合，初始上下文明确省略逐项证据、天气/碳细节并提供完整读取入口，保留准入阻断及全部原始事件。读取设计负荷仍须实际分页、当前hash和范围核验；不增大上下文或模型输出预算，不把摘要当作已读全量。最终原生请求验证仍待完成。

DL-005（高，漏页与错误缺失解释）：第三轮4B/8B各3题，两个有效运行题两模型都只读取offset=0的5/10行即结束。4B将未读的SPACE5-1说成结果中没有。复现及实际输出见`live-4b-v3.json`、`live-8b-v3.json`；不能以任务状态succeeded当作问题全部完成。预期未读页和确实缺失严格区分，读取覆盖与解释真实性分别核验。修复增加当前receipt_hash绑定的模型读取覆盖、首个未覆盖offset及有界纠错提醒；重读同页不重复计数、末页不代表前页已读、控制流程全量读取不计为模型已读。仅部分覆盖时任务完成状态为incomplete。已有运行核验的原生结果卡由当前服务端结果生成，模型文字仅保留审计；历史查询重新校验，失效后移除旧数值。这一修复不证明模型具有完整自由任务理解能力，仍待最终实际调用。

DL-006（高，运行列表状态矛盾）：同轮4B失效题反复读取并耗尽预算。`simulation_status`返回stale，而`simulation_list`仍使用持久化job的历史succeeded，误导当前有效性。复现：完成参考运行→撤回复核→分别调用上述两工具。预期均以当前来源判断有效性，历史执行完成状态另列。修复列表逐项调用当前domain.view，返回当前status，并把原job状态明确命名execution_status；不显示旧数值。专项用已执行成功但当前stale的反例核验。模型自行恢复和应用状态一致性分别记录，不将整个失败只归为模型表现。

覆盖修复后的第四轮进一步暴露DL-004的后续消息问题：初始请求和第一页已能执行，但保留提前结束的冗长数值解释，再请求续页时仍超8192，例如首题8287tokens；4B四个有效运行题失败、失效题通过。原始结果仍按版本保留，未以安全拒绝当作任务成功。随后只对模型消息采用无损列式编码（原行全部字段和值可重建，混合null采用兼容编码），每页约4303/4264字符；原字典与提前结束原文保留审计，后续上下文明确说明原文已移出而非静默截断。解释不再要求复制服务端结果卡中的大表。不得把这类协议/预算修复当作新增独立AI准确率。

第五轮两模型各5题，四个有效运行题均实际读取两页，但之后追加解释请求仍超窗口；失效题通过。4B在提前结束的审计原文中还曾把首行SPACE1-1数值误归给SPACE5-1，不能将这种文字视作正确解释。产品已将此类原文隔离在审计。进一步新增与既有专业交付一致的显式finish协议：模型在最后所需页主动请求finish，只有目标当前receipt的所有行真正被模型读取，控制器才接受；缺页、重复页、只读末页都不能完成。接着服务端再次读取当前结果，直接生成原生结果卡，无需为了复述数值追加模型请求。工具定义19948字符，原20000工具/64000消息/5轮15事件及8192模型窗口保持。最终真实调用仍须单列验证。

第四轮8B未实际启动：验收辅助程序在模型文件摘要检查后打开私有日志时目录不存在，根因未确定，记录于`live-8b-v4-harness-failure.json`。新辅助版本把新私有目录的创建与权限回读放到日志打开前；不补写或重算旧轮8B结果。
