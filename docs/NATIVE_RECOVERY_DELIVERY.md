## 修复前后的真实实验

通过随机本机端口访问真实 ASGI 服务，在独立数据库注册一次性测试账号，导入公开参考模型并发起真实年度计算。等到私有回执记录原生进程已启动，并取得精确的 Windows 进程句柄/Linux pidfd 后，强杀该测试服务。随后以同一个隔离数据库重启，核对中断任务、原件 SHA 和新任务结果。没有用 mock 计算或替代任务状态。

基线 Windows、Linux 各 10 项检查通过：原生进程已退出，中断运行显示失败且能耗/碳为空，新任务得到 57193.23 kWh，原件不变。但 Windows 在重启和正常停服后仍有 2 个私有临时目录、1 个 profile；Linux 有 2 个目录。最后由外层测试工具清理自己的临时资源，不计产品恢复成功。原始证据为 `validation/service-recovery-20261106/baseline-windows-v2` 与 `baseline-linux`。

初步候选在双平台各完成同一 10 项真实检查，重启和正常停止后的私有目录/profile 均为零。最终发布验收增加明确的零残留断言，并扩展至真实 DXF、OCR、PDF 三条 HTTP 处理链：每个平台能耗 12 项、DXF 13 项、OCR 13 项、PDF 12 项全部通过。重启与正常停服后均无任务目录/profile 遗留，解析公共代码缓存也被回收；永久空登记目录/锁文件不计任务残留。真实解析监督回执分别持有任务副本、控制目录、公共运行库的 3 个租约，能耗任务为 2 个。

## 实现

新增 `backend/native_ownership.py`：私有权限的版本化账本、文件身份、进程间注册锁、活动租约、资源回收及 Windows profile 身份核对。API lifespan 在启动工作线程之前恢复；EnergyPlus、CAD/BIM、PDF、OCR 的任务副本与公共代码缓存共用所有权协议。任务的监督器继承相关租约并核验身份，成功回执必须记录匹配的租约数量。原生任务仍只继承既定标准流/隔离握手，不持有管理租约。

分配与回收采用可重复检查的中间状态。回收资源后先删账本、最后删租约，以覆盖删除元数据期间的再次退出。未知身份、外链、损坏账本及不明资源保持原样并拒绝继续。不会终止一个靠重新查找 PID 得到的进程，也不会按历史目录/profile 的名称前缀删除资源。具体限制见恢复指南。

所有权、私有存储和路径检查模块加入物理/解析身份哈希；本批物理身份为 `2d4adcc9a9a171c627406e7f9ecca55fc958edcefe15111250e4a638a6291542`。原有已完成记录可能因此变为 stale，仍保留原 manifest 和结果；验收在新的源码快照及空运行目录建立真实参考链，不抬高原开发目录的归档额度，不改写旧索引。
