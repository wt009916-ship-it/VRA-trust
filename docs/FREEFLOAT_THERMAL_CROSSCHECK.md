# 无空调室温响应独立交叉验证

上批动态墙体基准夹定室内 20°C，不能验证自由漂移室温。本批使用公开合成几何：75 m³ 单区，六面总面积 110 m²；无热容量墙体热阻 0.4 m²K/W，内外表面换热系数分别 10、25 W/(m²K)，总传热系数为 1/0.54 W/(m²K)。无 HVAC、太阳、通风、潜热输入。空气热容量倍率 100 或 50 是研究假设，不是真实建筑热容校准。

## 独立答案

能量平衡为 C(T)dT/dt=UA(T外−T)+Q，C(T)=S/(T+273.15)，其中

S=V·倍率·p·cp/[287(1+1.6077687w)]，cp=1004.84+1858.95w，p=101325 Pa。

每段外温和内热保持常值。令 U=T+273.15、E=T外+Q/UA+273.15、k=UA/S，则精确段积分为

U下一步=E/[1+(E/U−1)exp(−kEΔt)]。

循环同一天日程至起止温差 <1e-12 K（最多 200 天）；以各步末温度形成小时平均，匹配此基准的原生报告采样约定。解析答案不读取 EnergyPlus 温度，也不复刻其离散算法。使用极干设计气象（干球/露点 −60°C）隔离湿度；原生空气物性下限 w=1e-5 来源于固定版本源代码。限定研究前提不代表一般湿空气动态工况。

固定版本来源：[空气热平衡实现](https://github.com/NREL/EnergyPlus/blob/v9.0.1/src/EnergyPlus/ZoneTempPredictorCorrector.cc)、[湿空气物性](https://github.com/NREL/EnergyPlus/blob/v9.0.1/src/EnergyPlus/Psychrometrics.hh)。只读下载哈希留在上一批 native-sources-v1.json。本批模型、答案、容差先冻结再原生运行。

## 失败与修正顺序

1. v1 保留恒温器并把控制置 0，8 例触发 Severe；即使引擎打印 Completed Successfully 也判失败。
2. v2 真正移除空调、恒温器及定容对象。温度计算出现可比较结果，但直接比较湿度上限把舍入尾差判为前提失败。所有原记录保留。
3. v3 使用 v2 完全相同输入与答案，新增预先写入 policy.json 的 1e-16 kg/kg 湿度舍入界；温度容差依然 0.02 K。该湿度区间内 |d ln C/dw|<4，容量相对扰动 <4e-16；用上界湿度重新积分，双精度结果与原答案的最大差为 0（不是宣称数学上的精确零）。新运行通过现有生产逐时解析器，不直接拼接成功数据。
4. Linux 以非特权 UID 65534 重放同一模型与 gold SHA，所有温度/负荷序列与 Windows 差为 0。

## 不能据此宣称的能力

不覆盖太阳辐射、渗透/机械通风、一般湿度耦合、复杂热桥、跨区空气交换、实楼测温校准、设备定容、当地规范符合性或舒适性认证。一般动态能力仍需更多独立公开基准及现场资料。既有全年 R1/R2 严格跨平台 1e-6 W 峰值一致性未通过的记录也不因本批一致而关闭。
