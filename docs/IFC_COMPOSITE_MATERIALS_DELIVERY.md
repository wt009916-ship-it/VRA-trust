## 实际能力

一个 IFC 梁／柱可以由不同材料构成。现在若有效材料轮廓集和实际恒截面扫掠体的复合轮廓一一匹配，软件可以分别生成各材料的原生扣洞／截切实体，检查网格，再核验空间并集。材料重叠、轮廓缺失、重复归属、缺材质和无法核验的网格都阻断整个汇总。不是按截面面积比例分配总量。

各分区保留原材料实体、材料轮廓、几何轮廓、Body、扫掠体及映射／截切路径 ID。模型来源按有效实例或类型声明解释，不按名称归并。分区结果复用既有单构件、墙板梁柱材料集合、两方案成本／碳和来源失效服务，不重复实现已有算术。

几何计算对每个材料建立私有表示路径，保留原放置、映射、DIFFERENCE 第二操作数及原开洞。源文件和共享几何均不修改。原生回执中新生成的表示 ID 属于临时副本，原始来源 ID 单列；报告解释复合材料片段编号是 IfcMaterialProfile，不是虚构层。

复合原始网格含材料接触界面，预验证五例整体网格均为 partial_mesh；这些原结果保留。没有把它们改标为通过。新方法明确以**完整来源分区的核验并集**计算整体体积，核验各分区为闭合实体、总和与并集一致，保留 union topology 回执。这与原始整体网格独立通过是两回事。

支持边界：最多16个平面域子轮廓、恒截面挤出、最多16级单路径映射／DIFFERENCE；分区三角形累计最多40000。沿用隔离 worker 的2 GiB／20秒CPU预算、原件快照及来源版本失效。变截面、任意多路径实体、嵌套复合轮廓、无精确声明对应的 BRep 仍拒绝。这里只测模型材料包络；钢筋、连接件、密度、损耗和采购规则不推断。

方法依据：[buildingSMART IFC4 ADD2 TC1 IfcBeam](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcsharedbldgelements/lexical/ifcbeam.htm)、[IfcMaterialProfileSet](https://standards.buildingsmart.org/IFC/RELEASE/IFC4_3/HTML/lexical/IfcMaterialProfileSet.htm)、[IfcOpenShell 几何处理](https://docs.ifcopenshell.org/ifcopenshell-python/geometry_processing.html)。本批只对使用的构造给出实现证据，不宣称 IFC 全标准认证。

## 缺陷与边界记录

### CMP-01 · 复合梁柱无法逐材计量（中，限定范围已实现）

- 功能：E04/E05/H01/H02。复现：上传含准确复合轮廓和两种材料的恒截面梁，申请材料计量。
- 预期：按实际空间分区扣洞、分材交付可追溯数量。
- 原实际：PR79返回 heterogeneous_member_material_partition_required，所有材料量未知。
- 当前实际：单侧洞12／10、跨材洞11／11、套筒芯9／13；异材重叠仍拒绝。
- 证据：core-first.log、additional-first.log、actual-http/、curved-native/，以及 tests/test_ifc_composite_materials.py。
- 修复：精确轮廓绑定、私有原生分区、全部覆盖及并集核验，接到原有材料服务。

### CMP-02 · 原始复合整体网格接触界面不满足原单体拓扑检查（方法限制，保留）

- 功能：E04。复现：native_feasibility.py的相邻材、套筒内芯等五例执行 inspect_shapes。
- 预期：不能把带重复接触界面的原始三角网格直接当作净实体。
- 实际：五例raw_whole_status为partial_mesh、体积null；分区单独原生可测。
- 证据：feasibility/result.json、原始合成IFC及脚本。
- 处理：原检查不放宽；新增明确标识的来源分区并集方法。任意模型原网格问题未宣称已修复。

### CMP-03 · 广泛复合表达及真实文件覆盖不足（中，开放）

- 功能：E04/E08/H01。复现：使用变截面、未能唯一绑定的BRep或缺CompositeProfile关系的多材构件。
- 预期：有充分几何来源时测量；无充分依据时保留缺口。
- 实际：当前拒绝，不按材名或比例臆造。新的外部复合模型、制造细节及专业净量规则尚未验收。
- 证据：参数拒绝测试与partition_reference的明确边界。
- 建议：下一次扩大几何域须先取得独立参照；不要为通过一个样本取消归属或拓扑门禁。
