# 下一子批预先计划：设计气象来源与适用性

本计划在 PR48 等待 CI 时建立，仅只读审计和准备，不改写 PR48 冻结源码或其验收记录。

现状已读：backend/design_loads.py 已提取设计日原始字段、设计日名称与原生 ZoneSizes 的绑定，以及 IDF 声明坐标/EPW 坐标比较；全部统计来源固定为 not_independently_verified。frontend/src/design-loads.js 显示“适用性待复核”。当前没有设计气象源文件（DDY）证据绑定链路。坐标一致和同名设计日不能替代来源证明。

已安装 EnergyPlus 9.0.1 WeatherData 内有 Golden、Chicago、Tampa、San Francisco、Sterling 五份 DDY 与 STAT。Golden DDY 注释声明 ASHRAE 2009 来源；只能记录该文件的自述及发行包来源，不能宣称它是当前适用设计标准。下一步先核验发行来源、字节和编码，再设计可重复匹配/冲突场景。

拟实现范围：独立导入设计条件资料与来源版本、按文件哈希/位置绑定具体模型设计日；展示逐字段一致/冲突/缺失，不把名称匹配当一致；统计出处、项目用途和规范适用性继续独立。修订/撤回源资料使其来源确认失效，不改写历史物理 run 或自动改换设计温度。

预先验证：公开多站点；同名异值、异名同值、日期/湿度类型/压力/风速/太阳模型/日程依赖变化；版本缺失、非法编码/截断/重复定义；字段差异应定位原文对象。只读原件保护、跨项目拒绝、旧报告当前重检，以及浏览器表单/导出。是否支持 DDY 的特定版本须由实际字段契约和引擎验证决定，不泛称所有版本兼容。

独立误差验证仍使用可解析稳态或受控动态模型，不以原生结果自己作为答案。复杂太阳/潜热与真实设计负荷未覆盖的部分保持待验证。

完成该批后转复杂 IFC 净工程量：现有 ifc_geometry.py 已启用原生开洞扣减并对单体网格做拓扑检查，但不处理跨构件重叠和专业扣减规则。先构造重叠开洞、穿出宿主、相切、重复关系、斜向/映射变换、空间聚合的独立几何金标准，识别“几何净体积”与“专业计量净量”的边界；不先把现有 volume_m3 改名为净工程量。

评分、扩大训练和全局视觉顺序保持原约定；公开参考不替代实楼或专家验收。
