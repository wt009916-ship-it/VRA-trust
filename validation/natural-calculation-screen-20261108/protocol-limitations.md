# 草案筛查的边界与审计记录

此协议是隔离实验，未注册产品路由，不具有业务写权限。通过来源校验只表示引用确实存在、位置唯一、数值及量纲可重算；不能证明引用属于模型声称的那一层/那一根梁。筛查用独立答案比较字段归属和任务覆盖，这个答案不发送给模型，也不是将来产品中可以凭空获得的事实。进入应用前仍须解决语义绑定与条件执行的审查方式。

N09只检验“仅草案”输入能否正确提取，因实验从未开放写能力，它不能证明真实Agent执行授权安全。N07仅为一条嵌入伪指令的合成案例，不能外推一般注入防护。缺失、矛盾、非法参数的分类与实际任务完成分开；回答澄清不计作计算完成。

## 已观察的测试设计限制（不改变冻结判据）

首次贪心N10参数与独立公式均正确，但已有engineering.calculate返回outside_model_screen：梁跨深比3.1/0.4=7.75，小于既有代码的适用性筛查阈值10。同批N04跨深比2.8/0.32=8.75亦如此。阈值是既有软件筛查，不是规范限值。测试器把两题均列为完整正例且强制要求status=calculated，导致即使正确提取也不可能得到strict通过。

事后诊断oracle-precondition-audit.json从冻结答案直接调用既有计算器，11个子任务的22个算术指标均与独立分数答案一致，N04及N10的梁状态被明确筛出。这不是模型重试，也不是修正后的正式成绩。保留原18题判定、原门槛、所有原始输出，不移除这两题抬高比例；对模型错误分类时须单列测试设计限制，不能报告为梁公式计算错误。

## 后续接受要求

本批只验证墙体与单集中力矩形梁的参数草案，不是全部建筑专业Agent能力。即使有配置达到冻结门槛，也只允许进入另行冻结的新应用验收；至少覆盖实际会话授权、两项任务、真实缺失澄清续答、服务/工具失败、记录保存及当前读取、来源变更撤回和输出范围。产品持久化前的任何输入变更均须重新绑定版本。不能把此处直接调用纯计算函数记为实际Agent工具链完成。
