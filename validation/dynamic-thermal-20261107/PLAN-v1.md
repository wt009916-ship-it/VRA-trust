# 动态热工与图纸错误边界：预先计划

基线main efa86d159070e44df1c0d7fd9d1786374005fbbe（PR46），复评76。原95+八维目标不变，训练与整体视觉后置。用户技能文件存在另行编辑，保持不动。原型18772正常，原业务表174条、任务3条；本批用C盘/无特权WSL独立目录保存大型运行，不改旧证据。

1. 先复现图纸重新处理表单的空手动角度错误路径。失败要进入可见错误处理，不发起计算；保存原失败、修复与复验。单元测试可用受控DOM/网络替身验证事件处理，但不得把替身称为真实OCR/浏览器验收。
2. 阅读固定EnergyPlus9.0.1文档、模型和实际SQLite结构，明确逐时温度、显热交付/需求变量、环境、单位、倍率与时钟含义。先原生探针再确定支持契约，不能照名称猜单位或倍率。
3. 设计全新动态输入，先冻结独立解析/数值参考、容差和时间步收敛检查，再运行引擎；至少覆盖热容量变化、内热扰动、变温边界和同步/错峰分区。保持无太阳等受控基准与一般实楼条件的区别；不以原生输出生成金标准。
4. 将已核验的原生逐时结果连到来源绑定的应用读取、统计/导出和界面。不能以年度能耗平均值推算动态峰值；未请求/缺失/单位错/时钟错/部分覆盖不得伪装完整结果。输入原件和原运行不覆写。
5. 新输入原生跨平台、恶意SQLite/文件、API归属与stale、前端/浏览器、回归和远端CI逐项验收，再评分和发布。变更计算版本时新跑独立年度参考，不重签旧运行。

范围尚在基线审计和原生探针阶段；本计划不是能力通过证明。公开/合成动态参考不能替代当地规范设计、实楼校准、净工程量、语义图纸修复、一般Agent注入或生产长期验收。
